## Кратко

Связывает страницу с внешним ресурсом. Чаще всего так подключают стили и фавиконки.

## Пример

```html
<head>
  <link rel="stylesheet" href="style.css">
</head>
```

## Как понять

Матёрые программисты советуют описывать CSS-стили в отдельных файлах: так их легче редактировать, сортировать и подключать к разным страницам сайта. Чтобы применить стили из внешнего файла на странице, используйте тег `<link>`.

Кроме стилей, `<link>` подключает другие ресурсы. Чаще всего это фавиконка и шрифт с внешнего сервера. Примеры — в разделе «[Примеры подключения](#primery-podklyucheniya)».

## Как пишется

`<link>` — одиночный тег, закрывающий тег ему не нужен. Обычно его пишут внутри [`<head>`](/html/head/). Указывайте атрибуты `rel` и `href`: первый говорит, зачем нужен ресурс, второй — где он лежит.

## Атрибуты

- `href` — адрес внешнего файла. Он может быть абсолютным `https://example.com/css/style.css` или относительным `css/style.css`.
- `rel` — говорит браузеру, как файл связан со страницей. Самые частые значения:
  - `stylesheet` — файл с CSS-стилями;
  - `icon` — фавиконка;
  - `apple-touch-icon` — иконка для главного экрана iPhone и iPad.
- `sizes` — сообщает размер фавиконки в пикселях, например `sizes="32x32"`. Атрибут ничего не меняет в картинке: по нему браузер выбирает подходящую фавиконку из нескольких. А `sizes="any"` сообщает, что фавиконка векторная и подходит для любого размера, например SVG.
- `media` — указывает устройство или условие, при котором работают стили. Например, `<link rel="stylesheet" href="mobile.css" media="screen and (max-width: 600px)">`.
- `as` — указывает тип загружаемого ресурса. По нему браузер расставляет приоритеты и планирует загрузку. Для `rel="preload"` атрибут `as` обязателен: без него браузер ничего не загрузит. Для [`rel="modulepreload"`](#predzagruzka-resursov-preload) — нет.
- `crossorigin` — загружает ресурс в режиме [CORS](/tools/cors/). Браузер проверит заголовки CORS в ответе сервера. Если нужных заголовков нет, браузер может заблокировать ресурс. Значения:
  - `anonymous` или атрибут без значения — запрос к другому origin (домену, протоколу или порту) без учётных данных: кук, заголовков аутентификации и клиентских сертификатов. Это может быть полезно для статических файлов, например изображений или шрифтов.
  - `use-credentials` — запрос с учётными данными. Сервер должен ответить заголовком `Access-Control-Allow-Credentials: true` и указать конкретный origin, а не `*`. Иначе браузер не применит ресурс.

Стилям и картинкам атрибут `crossorigin` обычно не нужен. Куки при их загрузке браузер отправляет и без него. Исключение — шрифты: браузер всегда загружает их в режиме CORS.

## Примеры подключения

Можно подключить альтернативные стили, например версию для слабовидящих. Переключать такие стили через меню умеет только Firefox: «Вид → Стиль страницы». В других браузерах переключатель придётся сделать на JavaScript.

```html
<link rel="stylesheet" href="default.css" title="Основной">
<link
  rel="alternate stylesheet"
  href="accessibility.css"
  title="Для слабовидящих"
>
```

Вот как можно подключить фавиконки для разных устройств. Для iPhone и iPad хватит одной картинки `apple-touch-icon` размером 180×180 пикселей. У `favicon.ico` укажите `sizes="32x32"`, а не `any`: иначе Chrome может выбрать ICO вместо SVG.

```html
<!-- Фавиконка для вкладки браузера -->
<link rel="icon" href="favicon.ico" sizes="32x32">
<!-- Векторная фавиконка там, где её поддерживают -->
<link rel="icon" href="icon.svg" type="image/svg+xml">
<!-- Иконка для главного экрана iPhone и iPad -->
<link rel="apple-touch-icon" href="apple-touch-icon.png">
```

Страница может выглядеть по-разному на разных устройствах. Для этого подключим разные стили в зависимости от устройства и размера экрана:

```html
<link rel="stylesheet" href="base.css" media="all">
<link rel="stylesheet" href="print.css" media="print">
<link
  rel="stylesheet"
  href="desktop.css"
  media="screen and (min-width: 600px)"
>
<link
  rel="stylesheet"
  href="highres.css"
  media="screen and (min-resolution: 2dppx)"
>
```

Вот как эти теги выглядят на странице целиком. Здесь `<link>` подключает:

- файл со стилями (`rel="stylesheet"`);
- RSS-ленту сайта (`rel="alternate"` с `type="application/rss+xml"`);
- фавиконку для вкладки браузера (`rel="icon"`).

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <title>Кулинарный блог</title>
  <link rel="stylesheet" href="style.css">
  <link
    rel="alternate"
    type="application/rss+xml"
    title="Статьи с сайта example.ru"
    href="https://example.ru/rss.xml"
  >
  <link rel="icon" href="https://example.ru/favicon.ico">
</head>
<body>
  <p>...</p>
</body>
</html>
```

## Оптимизация

Через `<link>` можно подсказать браузеру, что загрузить раньше, а что потом.

### Приоритет загрузки стилей с медиавыражениями

Можно указать тип устройства или [медиавыражение](/css/media/) в атрибуте `media`, как в примере со стилями для разных устройств выше. Браузер всё равно скачает все файлы стилей. Но файлы, условия которых сейчас не выполняются, он загрузит с низким приоритетом и не будет ждать их перед отрисовкой страницы.

Так можно разделить стили для [светлой и тёмной темы ОС](/css/prefers-color-scheme/). Браузер сначала загрузит файл для текущей темы и отрисует страницу, а второй файл скачает с низким приоритетом:

```html
<link
  rel="stylesheet"
  href="css/light.css"
  media="(prefers-color-scheme: light)"
>
<link
  rel="stylesheet"
  href="css/dark.css"
  media="(prefers-color-scheme: dark)"
>
```

### Предзагрузка ресурсов (`preload`)

`<link rel="preload">` говорит браузеру как можно скорее загрузить и кэшировать ресурс (например скрипт или файл стилей). Это полезно для ресурса текущей страницы, который браузер находит поздно. Например, для шрифта, который подключают в [`@font-face`](/css/font-face/), или фоновой картинки.

Браузер ничего не делает с ресурсом после загрузки. Скрипты не выполняются, стили не применяются. Браузер только кладёт ресурс в кэш и сразу отдаёт его, когда страница его запросит.

```html
<link
  rel="preload"
  href="fonts/roboto.woff2"
  as="font"
  type="font/woff2"
  crossorigin
>
```

У шрифта указывайте `crossorigin`, даже если он лежит на вашем домене. Без атрибута браузер скачает шрифт дважды. Со скриптами так же: у `<link rel="preload">` и у обычного [`<script>`](/html/script/) значение `crossorigin` должно совпадать. С модулями правило другое, о нём ниже.

Используйте предзагрузку, только когда ресурс понадобится сразу. Если страница не использует его в первые секунды после загрузки, Chrome напишет предупреждение в консоль.

Для JavaScript-модулей есть отдельное значение `modulepreload`:

```html
<link rel="modulepreload" href="app.js">
```

Браузер загрузит модуль заранее, разберёт и скомпилирует его, чтобы потом выполнить без задержки. Модули, которые он импортирует, браузер загружать не обязан. Их тоже перечисляйте в отдельных `<link rel="modulepreload">`.

Почему не `preload`: модули браузер всегда загружает в режиме CORS. `<link rel="preload" as="script">` без `crossorigin` скачает модуль дважды, а `modulepreload` загрузит его так же, как `<script type="module">`. Подробнее — в статье «[Модули, `import`/`export`](/js/modules/)».

### Загрузка ресурсов для следующей страницы (`prefetch`)

`<link rel="prefetch">` просит браузер загрузить и кэшировать ресурс в фоновом режиме. Браузер загружает его с низким приоритетом, поэтому не мешает более важным ресурсам. Это полезно, если ресурс понадобится на следующей странице, а вы хотите заранее его кэшировать.

Как и с `rel="preload"`, браузер ничего не делает с ресурсом после загрузки.

```html
<link rel="prefetch" href="next-page.css">
```

`prefetch` расходует трафик пользователя, который может стоить денег, поэтому загружайте заранее только то, что почти наверняка понадобится. В Safari `prefetch` по умолчанию выключен.

### Предварительное подключение к домену (`preconnect`)

`<link rel="preconnect">` просит браузер заранее подключиться к стороннему домену. Например, к Google Fonts или к серверу, с которого страница запрашивает JSON.

Открыть новое соединение обычно занимает несколько сотен миллисекунд. Если открыть его заранее, ресурсы с этого домена загрузятся быстрее.

```html
<link rel="preconnect" href="https://api.example.com">
```

Для домена со шрифтами добавьте `crossorigin`. Без него браузер откроет соединение, которое для шрифта не использует.

Не подключайтесь заранее ко всему подряд. Оставьте `preconnect` для нескольких самых важных доменов:

- каждое соединение требует DNS-запроса и установки защищённого соединения (TLS), а они отнимают у важных запросов пропускную способность сети и время процессора;
- неиспользованное соединение Chrome закроет через 10 секунд.

### Предварительное разрешение DNS (`dns-prefetch`)

`<link rel="dns-prefetch">` просит браузер заранее узнать IP-адрес домена. Это называют разрешением DNS. Пригодится для домена, с которого страница скоро что-то загрузит, например React из CDN — сети серверов для раздачи файлов.

Для каждого нового домена разрешение DNS обычно занимает около 20–120 мс. Это влияет только на загрузку первого ресурса с этого домена. Если разрешить DNS заранее, ресурс загрузится быстрее.

```html
<link rel="dns-prefetch" href="https://api.example.com">
```

Для самых важных доменов используйте `preconnect`: он уже включает разрешение DNS. Для остальных подойдёт `dns-prefetch`: он дешевле. Указывать оба значения для одного домена не нужно: `preconnect` поддерживают все современные браузеры.

### Пререндер страницы (`prerender`)

⚠️ Значение `prerender` устарело. Firefox и Safari его не поддерживают. Браузеры на Chromium только загружают страницу и её ресурсы: они не отрисовывают её и не выполняют JavaScript.

Чтобы браузер заранее отрисовал страницу, используйте Speculation Rules API (правила предварительной загрузки) в теге `<script type="speculationrules">`. Браузер отрисует страницу на невидимой вкладке, и после клика по ссылке она откроется сразу. Пререндер через такие правила поддерживают только браузеры на Chromium, например Chrome и Edge.

```html
<script type="speculationrules">
  {
    "prerender": [
      { "urls": ["/pricing"] }
    ]
  }
</script>
```

Но не злоупотребляйте такой возможностью! Пререндер расходует много трафика и памяти. Заранее готовьте только страницу, на которую пользователь почти наверняка перейдёт.

Когда браузер отрисовывает страницу заранее, её скрипты выполняются. Поэтому аналитика может засчитать просмотр, которого не было. Проверить, что пользователь страницу ещё не видел, можно через свойство `document.prerendering`.
