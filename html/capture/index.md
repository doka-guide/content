## Кратко

Атрибут `capture` работает у [`<input>`](/html/input/) с `type="file"`. С ним мобильный браузер сразу открывает камеру, а не окно выбора файла. Значение атрибута подсказывает, какую камеру взять: фронтальную или основную.

<aside>

📱 Работает только в мобильных браузерах.

</aside>

## Пример

Снимем видео на основную камеру смартфона:

```html
<label>
  Снимите видео
  <input type="file" accept="video/*" capture="environment">
</label>
```

## Как пишется

У атрибута два значения:

- `user` — камера, направленная на пользователя, то есть фронтальная;
- `environment` — камера, направленная от пользователя, то есть основная.

Если значение не указано или указано с ошибкой, камеру выберет браузер.

Что именно снимать, браузер узнаёт из атрибута [`accept`](/html/accept/): фото, видео или звук. Указывайте в нём один тип. С `accept="image/*,video/*"` Chrome на Android покажет окно выбора файла, а не камеру.

Так поле предложит сделать селфи:

```html
<label>
  Сделайте селфи
  <input type="file" accept="image/*" capture="user">
</label>
```

## Как понять

`capture` подходит, когда фото или видео нужно снять прямо сейчас, например селфи для профиля. Окно выбора файла при этом обычно не появится. Поэтому не ставьте атрибут там, где пользователю может понадобиться уже снятое фото.

Значение — только подсказка:

- Safari на iOS его учитывает;
- Chrome на Android не передаёт значение приложению камеры, и камеру выбирает само приложение;
- Firefox на Android, по отчётам разработчиков, ведёт себя так же, как Chrome.

Если нужной камеры на устройстве нет, браузер может открыть другую.

Страница не получает доступа к камере. Она получает только файл, который пользователь сам снял и подтвердил.

## Подсказки

💡 `accept` только подсказывает окну выбора файла, какие файлы показать. Отправить файл другого типа всё равно можно, поэтому тип файла проверяйте на сервере. Смотрите на содержимое файла, а не на расширение или заголовок `Content-Type`: их задаёт клиент.

💡 С `capture` атрибут [`multiple`](/html/multiple/) обычно ничего не даёт: браузер открывает камеру, а она возвращает один снимок. Несколько файлов выбирают в окне выбора файла.

💡 Запись звука через `accept="audio/*" capture` работает ненадёжно: если на телефоне нет приложения для записи звука, браузер может показать окно выбора файла. Голосовые сообщения надёжнее записывать через JavaScript: `getUserMedia()` и `MediaRecorder`. Они работают только по HTTPS и сами спрашивают у пользователя разрешение на микрофон.

💡 В фото с телефона может быть геопозиция: её записывают в метаданные файла. Safari на iOS может убрать координаты из снимка с камеры, но другие браузеры могут передать файл как есть. Поэтому удаляйте метаданные на сервере, прежде чем показать снимок другим пользователям.

## Поддержка браузеров

Десктопные браузеры атрибут не поддерживают. На мобильных он работает в Chrome, Firefox, Opera и Samsung Internet на Android и в Safari на iOS. Там, где поддержки нет, браузер покажет окно выбора файла, поэтому поле останется рабочим.
