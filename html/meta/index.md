## Кратко

В теге `<meta>` хранятся метаданные страницы: кодировка, краткое описание, настройки вьюпорта (окна просмотра) и другие данные для браузеров и поисковиков.

Метатегов на странице может быть много, но `charset` и `description` — только по одному. Обычно их размещают внутри тега [`<head>`](/html/head/).

## Пример

```html
<head>
  <meta charset="utf-8">
  <meta name="description" content="Краткое описание страницы">
  <meta
    name="viewport"
    content="width=device-width, initial-scale=1"
  >
</head>
```

## Как понять

Пользователь не видит содержимое метатегов на странице.

Метатеги различаются набором атрибутов и их значений. Один тег задаёт один параметр: например, имя автора `<meta name="author">` или время до перезагрузки страницы `<meta http-equiv="refresh">`.

Добавьте на страницу как минимум метатеги `charset`, `viewport` и `description`. Первый помогает браузеру правильно прочитать текст, второй — показать страницу на телефоне, третий — поисковикам составить описание страницы в выдаче.

В `<meta>` пишут то, что нельзя указать в [`<base>`](/html/base/), [`<link>`](/html/link/), [`<script>`](/html/script/), [`<style>`](/html/style/) или [`<title>`](/html/title/).

## Как пишется

Метатег с кодировкой состоит из одного атрибута `charset`:

```html
<meta charset="utf-8">
```

Остальные метатеги содержат атрибут `name` или `http-equiv` в паре с атрибутом `content`:

```html
<meta name="..." content="...">
<meta http-equiv="..." content="...">
```

Первый атрибут задаёт параметр, а второй — его значение. Вот как будет выглядеть метатег с описанием страницы:

```html
<meta
  name="description"
  content="Рассказываем, как нарезать картошку ломтиками"
>
```

В каждом теге должен быть ровно один из атрибутов `name`, `http-equiv`, `charset` или `itemprop`.

## Атрибуты

### `charset`

Задаёт кодировку страницы. В HTML допустимо только одно значение: `utf-8`. Регистр не важен, `UTF-8` тоже подойдёт.

### `content`

Значение метатега. Работает вместе с `name`, `http-equiv` или `itemprop`.

### `http-equiv`

Задаёт инструкцию для браузера. Основные значения:

- `"content-security-policy"` — [политика безопасности контента (CSP)](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP) для страницы. Тег работает только внутри `<head>` и защищает то, что браузер загрузит после него. Поэтому ставьте его до скриптов и стилей.
- `"default-style"` — название набора стилей, который браузер включит по умолчанию. В `content` указывают значение атрибута `title` у тега `<link rel="stylesheet">` или `<style>`.
- `"refresh"` — перезагрузка или переход на другую страницу через указанное число секунд.

Так браузер перезагрузит страницу через 30 секунд:

```html
<meta http-equiv="refresh" content="30">
```

После перезагрузки тег сработает снова, и страница будет обновляться по кругу.

Не делайте так на обычных страницах. Если человек не может отключить обновление, это нарушение [WCAG](/a11y/wcag/) — правил доступности веб-контента. После перезагрузки [скринридер](/a11y/screenreaders/) начинает читать страницу с начала, а введённый в формы текст пропадает.

Если добавить в `content` адрес, браузер перейдёт на него:

```html
<meta http-equiv="refresh" content="0; url=https://doka.guide/">
```

### `name`

Имя метатега, которое определяет, что лежит в `content`. Основные значения:

- `"description"` — краткое описание страницы. Поисковики могут показать его под заголовком в выдаче. Google не учитывает описание, когда решает, на каком месте показать страницу.
- `"viewport"` — параметры вьюпорта на мобильных устройствах. `width=device-width` задаёт ширину страницы по ширине экрана, а `initial-scale=1` — масштаб при первом открытии.
- `"author"` — имя автора страницы, например `<meta name="author" content="Иван Петров">`.
- `"keywords"` — ключевые слова страницы. Google не учитывает этот метатег с 2009 года. Яндекс в справке пишет, что тег может влиять на соответствие страницы запросу. Заполнять его не обязательно.

⚠️ Не запрещайте масштаб в `viewport` через `maximum-scale=1` или `user-scalable=no`. Людям с плохим зрением нужно увеличивать текст пальцами. Safari на iOS эти запреты игнорирует, а Chrome и Firefox на Android по умолчанию выполняют.

### `itemprop`

Задаёт свойство микроданных — разметки для поисковиков из стандарта HTML. Значение такого свойства не нужно показывать на странице.

Метатег с `itemprop` может стоять и в [`<body>`](/html/body/), обычно внутри элемента с [атрибутом `itemscope`](/html/global-attrs/). Названия свойств обычно берут из словаря [Schema.org](https://schema.org/):

```html
<div itemscope itemtype="https://schema.org/Product">
  <span itemprop="name">Чайник</span>
  <meta itemprop="sku" content="KT-2024">
</div>
```

### `media`

[Медиазапрос](/css/media/), при котором метатег работает. Сейчас его учитывают только у `<meta name="theme-color">` — цвета интерфейса браузера. Например, так можно задать разный цвет для светлой и тёмной темы:

```html
<meta
  name="theme-color"
  content="#ffffff"
  media="(prefers-color-scheme: light)"
>
<meta
  name="theme-color"
  content="#18191c"
  media="(prefers-color-scheme: dark)"
>
```

Этот цвет учитывают в основном Chrome на Android и установленные веб-приложения. Firefox его не поддерживает.

## Подсказки

💡 Метатег с атрибутом `charset` должен целиком помещаться в первых 1024 байтах документа. Иначе браузер может начать читать страницу в другой кодировке. Ставьте его первым в `<head>`.

💡 Для перехода на другой адрес используйте серверный редирект с кодом 301 или 308, если можете. Переход через `<meta http-equiv="refresh">` с задержкой сбивает пользователей: страница меняется, пока человек её читает.

💡 Значения `http-equiv` только похожи на [HTTP-заголовки](/tools/http-protocol/). Например, часть директив CSP, вроде `frame-ancestors`, в теге `<meta>` не работает: их задают только HTTP-заголовком.
