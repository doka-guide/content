## Кратко

Атрибут `rel` описывает, как связаны текущая страница и ресурс, на который указывает ссылка. Работает с [`<a>`](/html/a/), [`<link>`](/html/link/), [`<area>`](/html/area/) и [`<form>`](/html/form/).

## Пример

```html
<link rel="stylesheet" href="styles.css">
<a href="https://example.com" rel="external nofollow">
  Сайт, за который мы не ручаемся
</a>
```

## Для чего нужен атрибут `rel`

**Определение типа ресурса:** значение `rel="stylesheet"` указывает браузеру, что подключаемый файл — это таблица стилей.

**Подсказки поисковикам:** значение `rel="nofollow"` говорит поисковикам, что автор не ручается за ссылку.

**Безопасность:** значение `rel="noopener"` не даёт открытой странице управлять исходной.

**Ускорение загрузки:** значение `rel="preload"` говорит браузеру заранее загрузить ресурсы, которые он иначе нашёл бы поздно, например шрифты из CSS. Так страница быстрее появится на экране.

**Управление навигацией:** `rel="next"` и `rel="prev"` связывают страницы в последовательность. В 2019 году Google объявил, что давно их не использует, но в стандарте HTML они остались.

## Как пишется

Значения можно комбинировать через пробел.

```html
<link
  rel="alternate stylesheet"
  href="night-theme.css"
  title="Ночная тема"
>
```

## Значения

### `alternate`

Указывает на альтернативную версию текущего документа.

**Альтернативная таблица стилей (через `<link>`):** позволяет выбрать другую тему оформления.

Если у альтернативных стилей указан атрибут `title`, Firefox покажет их в меню «Вид → Стиль страницы», и пользователь сможет переключаться между ними. Другие браузеры такого меню не показывают, там альтернативные стили включают скриптом.

```html
<head>
  <link rel="stylesheet" href="main.css">
  <link
    rel="alternate stylesheet"
    href="dark.css"
    title="Тёмная тема"
  >
  <link
    rel="alternate stylesheet"
    href="large-fonts.css"
    title="Крупный текст"
  >
</head>
```

**RSS- и Atom-ленты (через `<link>`):** когда значение `alternate` сочетается с `type="application/rss+xml"` или `type="application/atom+xml"`, RSS-ридеры понимают, что элемент `<link>` указывает на ленту новостей для подписки.

Как это работает:

- RSS-ридеры и расширения браузера находят ленту, когда пользователь добавляет адрес сайта;
- атрибут `title` задаёт понятное человеку название ленты.

```html
<head>
  <!-- Atom-лента -->
  <link
    rel="alternate"
    type="application/atom+xml"
    href="https://example.com/feed.atom"
    title="Блог — Atom-лента"
  >

  <!-- RSS-лента -->
  <link
    rel="alternate"
    type="application/rss+xml"
    href="https://example.com/feed.xml"
    title="Блог — RSS-лента"
  >
</head>
```

**Языковые версии статьи:** атрибут `hreflang` подсказывает поисковикам, на каком языке каждая версия. Google покажет испаноязычным пользователям испанскую версию, а англоязычным — английскую. Каждая версия должна ссылаться на все остальные и на себя.

```html
<head>
  <link
    rel="alternate"
    hreflang="en"
    href="https://example.com/en/article-quantum-physics"
  >
  <link
    rel="alternate"
    hreflang="es"
    href="https://example.com/es/articulo-fisica-cuantica"
  >
</head>
```

**PDF-версия инструкции:** значение сообщает, что по ссылке та же инструкция в другом формате. Браузеры такую ссылку никак не выделяют, поэтому формат файла нужно написать в тексте ссылки.

```html
<a href="/manual.pdf" rel="alternate" type="application/pdf">
  Скачать инструкцию в PDF
</a>
```

### `author`

Показывает, где найти информацию об авторе страницы или статьи. Работает с элементами `<link>`, `<a>` и `<area>`.

**Ссылка на автора (через `<link>`):** добавляет метаинформацию об авторе всей страницы. Чаще всего ведёт на почту или профиль автора.

```html
<head>
  <!-- Ссылка на страницу автора -->
  <link rel="author" href="/about-igor">

  <!-- Email для связи -->
  <link rel="author" href="mailto:igor@example.com">
</head>
```

**Указание автора статьи (через `<a>`):** если статья обёрнута в [`<article>`](/html/article/), ссылка с `rel="author"` будет относиться к её автору. Иначе — к автору всей страницы.

```html
<!-- Автор статьи внутри <article> -->
<article>
  <h1>Как вырастить авокадо</h1>
  <p>
    Автор:
    <a href="/profile/anna" rel="author">
      Анна Иванова
    </a>
  </p>
</article>

<!-- Email автора в подвале сайта -->
<footer>
  <a href="mailto:author@example.com" rel="author">
    Написать автору
  </a>
</footer>
```

### `bookmark`

Значение `rel="bookmark"` работает с элементами `<a>` и `<area>`.

**Создание постоянной ссылки:** значение помечает ссылку на часть страницы как постоянную. Такая ссылка ведёт к ближайшему `<article>`, внутри которого она стоит. Если такого `<article>` нет, ссылка ведёт к разделу, в котором стоит.

```html
<!-- Ссылка на раздел без <article> -->
<section id="tips">
  <h2>Советы по вёрстке</h2>
  <p>Текст раздела...
    <a href="#tips" rel="bookmark">
      Постоянная ссылка на этот раздел.
    </a>
  </p>
</section>

<!-- Ссылка внутри <article> (запись блога) -->
<article id="post-1">
  <h2>Как печь хлеб</h2>
  <p>Рецепт...
    <a href="#post-1" rel="bookmark">
      Постоянная ссылка на эту запись.
    </a>
  </p>
</article>
```

### `canonical`

Значение `rel="canonical"` указывает поисковикам основную версию страницы. Работает с элементом `<link>`.

Например, `example.com/page` и `example.com/page?utm=1` показывают одно и то же. Каноническая ссылка говорит, какой из адресов считать основным. Так копии не соперничают между собой в поисковой выдаче.

Канонический адрес может вести и на другой домен, если контент размещён на нескольких сайтах.

Правила использования:

1. Контент канонической страницы должен совпадать с текущей. Иначе поисковики проигнорируют указание.
1. На странице должна быть одна каноническая ссылка. Если их несколько, Google, скорее всего, проигнорирует все.
1. Канонический адрес должен возвращать код `200 OK`. Страницу с ошибкой, например `404`, поисковики не обработают.
1. Используйте абсолютные адреса. Относительные тоже работают, но могут сломаться при копировании кода между страницами.

```html
<head>
  <link rel="canonical" href="https://example.com/main-page">
</head>
```

### `dns-prefetch`

Значение `rel="dns-prefetch"` помогает ускорить загрузку сайта. Добавьте его в элемент `<link>`, чтобы браузер заранее узнал IP-адрес домена. Это как сохранить номер телефона в быстром наборе — не придётся искать его, когда понадобится позвонить.

Как это работает:

1. DNS-запрос. Когда вы вводите адрес сайта (например, `example.com`), браузер ищет его IP-адрес через систему DNS.
1. Запрос заранее. С `dns-prefetch` браузер делает этот запрос ещё до того, как ресурс понадобится.
1. Экономия времени. Когда ресурс действительно понадобится (например, для загрузки шрифта), браузер уже знает, куда обращаться.

`dns-prefetch` пригодится, если страница берёт ресурсы с других доменов:

- шрифты, скрипты или картинки;
- видео или аудио с внешних платформ, например YouTube или Vimeo;
- API, если сайт сделан как SPA (_single page application_).

Например, так браузер заранее узнает адреса Google Fonts и YouTube:

```html
<head>
  <!-- Заранее узнать адрес Google Fonts -->
  <link rel="dns-prefetch" href="https://fonts.googleapis.com">

  <!-- Заранее узнать адрес YouTube -->
  <link rel="dns-prefetch" href="https://www.youtube.com">
</head>
```

**Адрес с протоколом и без:** можно указывать домен с протоколом или без.

```html
<head>
  <!-- Без протокола -->
  <link rel="dns-prefetch" href="//example.com">

  <!-- С протоколом -->
  <link rel="dns-prefetch" href="https://api.example.com">
</head>
```

> Указывайте только те домены, которые реально понадобятся. Слишком много DNS-запросов могут замедлить начальную загрузку страницы. Для самых важных доменов используйте [`preconnect`](#preconnect): он не только узнаёт адрес, но и открывает соединение.

### `expect`

Значение `rel="expect"` работает с элементом `<link>`. Оно указывает, что элемент из атрибута `href="#id-элемента"` важен для первой отрисовки страницы.

Значение работает только вместе с атрибутом `blocking="render"`. Тогда браузер не рисует страницу, пока не разберёт указанный элемент. Чаще всего это нужно для [переходов между страницами](/css/view-transition/): анимация перехода начнётся, когда важная часть страницы уже готова.

Браузер блокирует отрисовку, пока выполняются все условия:

- у `<link>` есть `blocking="render"`;
- `<link>` стоит в [`<head>`](/html/head/) разметки: если скрипт добавит его после начала `<body>`, отрисовка не заблокируется;
- `href` ведёт на текущий документ: пишите только `#id`, адрес с путём сработает, только если он совпадает с адресом страницы;
- элемент с ID из `href` ещё не появился в DOM или ещё не разобран до конца;
- документ ещё загружается;
- атрибут `media`, если он есть, соответствует текущим условиям, например размеру экрана.

Здесь браузер задержит отрисовку, пока не разберёт элемент с `id="lead-content"`, а на широких экранах — ещё и `id="first-section"`.

```html
<head>
  <link rel="expect" href="#lead-content" blocking="render">
  <link
    rel="expect"
    href="#first-section"
    blocking="render"
    media="(width > 640px)"
  >
</head>
<body>
  <div id="lead-content">Главное</div>
  <section id="first-section">Первая секция</section>
</body>
```

Особые случаи:

- `href` у `<link rel="expect">` изменили до того, как браузер разобрал целевой элемент: браузер ждёт элемент с новым ID.
- `href` изменили после того, как целевой элемент разобран: блокировка уже снята, изменение ни на что не влияет.
- Элемент с указанным ID не найден: блокировка закончится, когда браузер разберёт весь документ.
- Несколько элементов с одним ID: браузер ждёт первый из них. Держите ID уникальными.
- Браузер ждёт слишком долго: он может снять блокировку раньше, по своему таймауту.

Работает в Chrome и Edge с версии 124 и Safari с версии 18.2. Firefox поддержит его с версии 162, она выходит в декабре 2026 года.

### `external`

Значение `rel="external"` работает с элементами `<a>`, `<area>` и `<form>`. Оно помечает ссылку как внешнюю, то есть ведущую на сайт, не связанный с текущим.

Браузеры такие ссылки никак не выделяют. Значение пригодится для стилей и скриптов: например, по селектору `a[rel~="external"]` можно добавить внешним ссылкам иконку. Тогда пользователь заранее увидит, что окажется на другом сайте.

В примере ниже ссылка помечена как внешняя.

```html
<a href="https://www.wikipedia.org" rel="external">
  Посетить Wikipedia
</a>
```

Внешней может быть и ссылка-картинка.

```html
<figure>
  <a
    href="https://www.unsplash.com"
    rel="external"
    target="_blank"
  >
    <img
      src="https://images.unsplash.com/photo-172"
      alt="Горное озеро на рассвете"
    >
  </a>
  <figcaption>
    Изображение с Unsplash
  </figcaption>
</figure>
```

Здесь форма отправляет данные на сайт _example.com_, поэтому форму тоже помечают `rel="external"`.

```html
<form
  action="https://www.example.com/submit"
  method="post"
  rel="external"
>
  <label for="name">Имя:</label>
  <input type="text" id="name" name="name">
  <input type="submit" value="Отправить">
</form>
```

### `help`

Значение `rel="help"` работает с элементами `<link>`, `<a>`, `<area>` и `<form>`. Оно обозначает ссылку на страницу с дополнительной информацией или инструкцией, которая поможет пользователю разобраться с функциями на сайте.

Браузеры такие ссылки никак не выделяют.

**Ссылка на помощь по теме:** ссылка ведёт на страницу с дополнительной информацией о теме, которую пользователь вводит в поле.

```html
<p>
  <label>
    Тема:
    <input name="topic">
    <a href="help/topic.html" rel="help">Помощь по теме</a>
  </label>
</p>
```

**Ссылка на помощь по заполнению формы:** ссылка ведёт на страницу, которая объяснит, как правильно заполнить форму. Это полезно для тех, кто может не понять, что именно нужно ввести.

```html
<form>
  <label for="name">Имя:</label>
  <input type="text" id="name" name="name">

  <a href="help/form_help.html" rel="help">Помощь с формой</a>

  <button type="submit">Отправить</button>
</form>
```

**Ссылки на общую помощь по сайту:** ссылки ведут на страницы помощи, которые объясняют, как пользоваться сайтом или как найти нужную информацию.

```html
<ul>
  <li>
    <a href="help/site_navigation.html" rel="help">
      Помощь с навигацией
    </a>
  </li>
  <li>
    <a href="help/content.html" rel="help">
      Помощь с содержимым
    </a>
  </li>
</ul>
```

### `icon`

Значение `rel="icon"` сообщает браузеру, где взять иконку для страницы. Работает с элементом `<link>`. Можно подключить несколько иконок: формат задаёт атрибут `type`, а размеры — атрибут `sizes`.

Значения в атрибуте `sizes` указывают реальные размеры картинки в пикселях, а не размеры в CSS. У SVG-иконки нет фиксированного размера: для неё подходит значение `any`, а можно и не указывать `sizes` вовсе.

В примере показано, как подключить иконку в двух форматах. Браузер, который понимает SVG, возьмёт её, остальные — ICO. Для иконки на домашнем экране iPhone используют отдельное значение `rel="apple-touch-icon"` с картинкой 180 × 180 пикселей.

```html
<head>
  <link rel="icon" href="/favicon.ico" sizes="32x32">
  <link rel="icon" href="/icon.svg" type="image/svg+xml">
  <link rel="apple-touch-icon" href="/apple-touch-icon.png">
</head>
```

### `license`

Значение `rel="license"` ведёт на условия лицензии. Работает с элементами `<link>`, `<a>`, `<area>` и `<form>`.

Ссылка с `rel="license"` описывает лицензию основного содержимого страницы. В примере ниже на странице одна фотография, и лицензия относится к ней.

```html
<figure>
  <img
    src="/images/cats.jpg"
    alt="Два кота спят на подоконнике"
  >
  <figcaption>Коты на подоконнике</figcaption>
</figure>
<a
  rel="license"
  href="https://creativecommons.org/licenses/by/4.0/"
>
  Лицензия CC BY 4.0
</a>
```

### `manifest`

Значение `rel="manifest"` работает с элементом `<link>` и указывает на манифест веб-приложения.

Манифест — это JSON-файл с информацией о приложении: название, иконки, цвета, стартовая страница и режим отображения. По нему браузер устанавливает сайт на устройство как приложение.

Работу без сети манифест не настраивает: для этого нужен сервис-воркер. Подробнее — в статье о [прогрессивных веб-приложениях](/tools/pwa/).

```html
<head>
  <link rel="manifest" href="/manifest.json">
</head>
```

### `modulepreload`

Значение `rel="modulepreload"` работает с элементом `<link>`. Браузер заранее скачивает и разбирает модульные скрипты, и приложение запускается быстрее.

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <link rel="modulepreload" href="app.mjs">
  <link rel="modulepreload" href="awesome-viewer.mjs">
</head>
<body>
  <script type="module" src="app.mjs"></script>
  <button
    onclick="import('./awesome-viewer.mjs').then(m => m.view())"
  >
    Просмотр удивительной вещи
  </button>
</body>
</html>
```

Здесь браузер загрузит `app.mjs` и `awesome-viewer.mjs` сразу. Когда пользователь нажмёт кнопку, динамический `import()` возьмёт уже загруженный модуль, и интерфейс откликнется без задержки.

Зависимости модуля браузер может загрузить сам, но не обязан. Важные зависимости перечислите отдельными `<link rel="modulepreload">`: тогда браузер загрузит их параллельно, а не по цепочке.

### `nofollow`

Значение `rel="nofollow"` работает с элементами `<a>`, `<area>` и `<form>`. Оно сообщает поисковикам, что автор страницы не ручается за ссылку. Например, так помечают ссылки в комментариях и ссылки на ненадёжные ресурсы. Тогда спам-ссылки не влияют на репутацию сайта.

В этом примере ссылка на сайт _example.com_ помечена как `nofollow`.

```html
<p>
  Смотрите этот
  <a href="https://example.com" rel="nofollow">
    внешний сайт
  </a>
  для дополнительной информации.
</p>
```

Здесь ссылка на сомнительный сайт тоже помечена `nofollow`.

```html
<p>
  <a href="https://spam.example" rel="nofollow">
    Ссылка на сомнительный сайт
  </a>
</p>
```

С 2019 года Google считает `nofollow` подсказкой, а не запретом: он может учесть такую ссылку. Для точности Google предлагает ещё два значения:

- `rel="sponsored"` — для рекламных и партнёрских ссылок;
- `rel="ugc"` — для ссылок от пользователей, например в комментариях.

Их нет в стандарте HTML, но Google их учитывает.

### `noopener`

Значение `rel="noopener"` работает с элементами `<a>`, `<area>` и `<form>`. Оно не даёт открытой странице получить доступ к объекту `window.opener` — ссылке на исходную страницу. С таким доступом чужая страница может, например, подменить адрес исходной вкладки на фишинговый.

Для ссылок с `target="_blank"` все браузеры ставят `noopener` сами: Chrome с версии 88, Firefox с версии 79 и Safari с версии 12.1. Явно писать его нужно для `target` с именем окна, например `target="help"`, или чтобы защитить пользователей очень старых браузеров.

```html
<a href="https://example.com" target="help" rel="noopener">
  Перейти на Example.com
</a>
```

### `noreferrer`

Значение `rel="noreferrer"` работает с элементами `<a>`, `<area>` и `<form>`.

При переходе по ссылке с этим значением браузер не отправляет заголовок `Referer`.

По умолчанию браузеры и так передают чужому сайту только адрес сайта (протокол, домен и порт) без пути и параметров. При переходе с HTTPS на HTTP не передают ничего. С `noreferrer` сайт не узнает даже адрес.

Ещё `noreferrer` включает `noopener`: новая страница не получает доступа к объекту `window.opener` исходной страницы.

В этом примере работают обе защиты.

```html
<a href="https://example.com" target="_blank" rel="noreferrer">
  Перейти на Example.com
</a>
```

### `opener`

Значение `rel="opener"` работает с элементами `<a>`, `<area>` и `<form>`. Оно отменяет `noopener`, который браузеры ставят по умолчанию для `target="_blank"`.

Новая вкладка получит доступ к исходной странице через `window.opener`. Например, страница помощи сможет обновить содержимое исходной вкладки. Используйте значение только для ссылок на свои страницы.

Здесь _help.html_ откроется в новой вкладке и сможет управлять исходной страницей.

```html
<a href="help.html" rel="opener" target="_blank">
  Помощь!
</a>
```

### `pingback`

Значение `rel="pingback"` работает с элементом `<link>`. Оно указывает адрес, который принимает уведомления, когда другой сайт ссылается на вашу страницу.

Такие уведомления отправляет движок чужого сайта, например WordPress. Так автор узнаёт, что на его материал сослались.

Если уведомления не нужны, отключите их в настройках движка: через него проводят DDoS-атаки на чужие сайты.

```html
<head>
  <link rel="pingback" href="https://example.com/pingback">
</head>
```

### `preconnect`

Значение `rel="preconnect"` работает с элементом `<link>`. Браузер заранее открывает соединение с сервером, и ресурсы с него потом загружаются быстрее.

При подготовке соединения браузер:

- узнаёт IP-адрес домена через DNS;
- открывает [TCP-соединение](/tools/tcp-udp-protocols/);
- для HTTPS договаривается с сервером о шифровании (TLS-рукопожатие).

Для шрифтов и других запросов в режиме [CORS](/tools/cors/) добавьте атрибут [`crossorigin`](/html/crossorigin/). Без него браузер подготовит не то соединение, и для шрифта откроет ещё одно.

```html
<head>
  <link
    rel="preconnect"
    href="https://fonts.gstatic.com"
    crossorigin
  >
</head>
```

### `prefetch`

Значение `rel="prefetch"` работает с элементом `<link>`. Оно говорит браузеру заранее загрузить ресурсы, которые могут понадобиться пользователю позже. Например, перед переходом на новую страницу или перед загрузкой тяжёлых медиафайлов.

Браузер загружает такой ресурс в фоне с низким приоритетом и кэширует его. Когда ресурс понадобится, он загрузится быстрее.

Фоновая загрузка почти не мешает текущей странице, но тратит трафик пользователя. Это подсказка: браузер может её пропустить.

В Safari `prefetch` по умолчанию выключен: его можно включить только в экспериментальных настройках браузера.

```html
<head>
  <link
    rel="prefetch"
    href="https://example.com/future-resource"
  >
</head>
```

### `preload`

Значение `rel="preload"` работает с элементом `<link>`. Браузер сразу загружает ресурс, который точно понадобится на текущей странице.

Это полезно для ресурсов, которые браузер находит поздно: шрифтов и фоновых картинок из CSS, модулей, которые подгружает другой скрипт. То, что уже стоит в `<head>`, загружать заранее незачем.

Приоритет загрузки зависит от типа ресурса. Браузер загружает ресурс, но не применяет его, пока он не понадобится.

Тип ресурса задаёт атрибут `as`: `style`, `script`, `font`, `image`, `fetch` или `track`. Без `as` браузер не загрузит ресурс. Если `as` не совпадает с тем, как ресурс используют, браузер скачает его второй раз.

```html
<head>
  <link rel="preload" href="hero.webp" as="image">
  <link
    rel="preload"
    href="font.woff2"
    as="font"
    type="font/woff2"
    crossorigin="anonymous"
  >
</head>
```

У шрифтов нужен атрибут `crossorigin`: браузер загружает их в режиме CORS и без атрибута скачает файл второй раз.

### `search`

Значение `rel="search"` работает с элементами `<link>`, `<a>`, `<area>` и `<form>`. Оно ведёт на поиск по сайту.

`<link>` с `rel="search"` сообщает браузеру, что на сайте есть поиск. Описание поиска лежит в XML-файле формата OpenSearch. Браузер, который понимает этот формат, может предложить добавить поиск по сайту в список поисковых систем.

```html
<head>
  <link
    rel="search"
    type="application/opensearchdescription+xml"
    href="/search.xml"
    title="Поиск по сайту"
  >
</head>
```

### `stylesheet`

Значение `rel="stylesheet"` работает с элементом `<link>` и подключает внешнюю таблицу стилей.

Как это работает:

- указывает, что ресурс — таблица стилей;
- если `<link>` стоит в `<head>`, браузер не рисует страницу, пока стили не загрузятся и не обработаются, кроме альтернативных стилей и стилей с неподходящим `media`;
- позволяет не указывать `type="text/css"`, так как браузер и без него считает файл CSS;
- вместе с `alternate` и атрибутом `title` задаёт альтернативные таблицы стилей.

Если нужно **предложить несколько вариантов оформления**:

```html
<head>
  <link
    rel="stylesheet"
    href="light-theme.css"
    title="Светлая тема"
  >
  <link
    rel="alternate stylesheet"
    href="dark-theme.css"
    title="Тёмная тема"
  >
</head>
```

Если некритичный **CSS должен загружаться без блокировки отрисовки**:

```html
<head>
  <link
    rel="preload"
    href="styles.css"
    as="style"
    onload="this.onload=null;this.rel='stylesheet'"
  >
  <noscript>
    <link rel="stylesheet" href="styles.css">
  </noscript>
</head>
```

Приём работает только с включённым JavaScript, поэтому для остальных случаев нужен [`<noscript>`](/html/noscript/). Если [политика безопасности контента (CSP)](/tools/web-security/) запрещает встроенные обработчики, `onload` не сработает.

### `tag`

Значение `rel="tag"` работает с элементами `<a>` и `<area>`. Оно показывает, что ссылка ведёт на страницу тега, которым помечен текущий документ.

Ставьте значение только на теги текущего документа, а не на облако популярных тегов. Оно пригодится в блогах, каталогах и статьях.

```html
<footer>
  Теги:
  <a rel="tag" href="https://example.com/tag/technology">
    Технологии
  </a>
</footer>
```

### `terms-of-service`

Значение `rel="terms-of-service"` работает с элементами `<link>`, `<a>` и `<area>`. Оно помечает ссылку на условия использования (Terms of Service, ToS).

Такую ссылку обычно ставят в подвал сайта рядом с политикой конфиденциальности. Для политики есть своё значение `rel="privacy-policy"`.

```html
<footer>
  <a rel="terms-of-service" href="/terms">
    Условия использования
  </a>
  <a rel="privacy-policy" href="/privacy">
    Политика конфиденциальности
  </a>
</footer>
```

### `next` и `prev`

Значения `next` и `prev` связывают документы в цепочку, например страницы каталога или главы книги.

**Значение `next`:** ссылка ведёт к следующему документу цепочки. Работает с `<link>`, `<a>`, `<area>` и `<form>`.

```html
<head>
  <link rel="next" href="document2.html">
</head>
<body>
  <a rel="next" href="document2.html">
    Следующий документ
  </a>
</body>
```

**Значение `prev`:** ссылка ведёт к предыдущему документу цепочки. Работает с теми же элементами, что и `next`.

```html
<head>
  <link rel="prev" href="document1.html">
</head>
<body>
  <a rel="prev" href="document1.html">
    Предыдущий документ
  </a>
</body>
```

Google не использует `prev` и `next` для индексации. Bing в 2019 году сообщил, что использует их как подсказку для обхода сайта, но не для ранжирования.

Спецификация советует браузерам обрабатывать `<link rel="next">` как `dns-prefetch`, `preconnect` или `prefetch`, а что выбрать, решает браузер. Ещё значения могут использовать браузерные расширения и ваши скрипты, например для навигации по страницам с клавиатуры.
