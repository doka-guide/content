## Кратко

Атрибуты `defer` и `async` говорят браузеру не останавливать разбор HTML, пока скачивается скрипт. Скрипты с `defer` выполняются по порядку, когда весь HTML разобран. Скрипты с `async` выполняются сразу, как только браузер их скачает, в любом порядке.

## Пример

```html
<head>
  <script src="app.js" defer></script>
  <script src="analytics.js" async></script>
</head>
```

## Как пишется

Оба атрибута логические: браузер проверяет, есть ли атрибут, а значение не читает. Даже `async="false"` включает `async`. Чтобы отменить эффект, уберите атрибут.

Атрибуты работают у внешних скриптов, то есть у [`<script>`](/html/script/) с атрибутом `src`. У обычного встроенного скрипта браузер их не учитывает. Исключение — скрипты-[модули](/js/modules/) с `type="module"`, о них в подсказках.

## Как понять

Без атрибутов скрипт блокирует разбор HTML. Браузер доходит до `<script src="...">` и не разбирает HTML дальше, пока скрипт не скачается и не выполнится. Поэтому раньше скрипты ставили в конец страницы, перед [`</body>`](/html/body/), чтобы они не задерживали её показ.

С `defer` и `async` браузер скачивает скрипт параллельно с разбором HTML. Разница в том, когда скрипт выполнится.

### Атрибут `async`

Как только скрипт скачан, браузер выполняет его. На время выполнения разбор HTML всё же останавливается.

```html
<script src="analytics.js" async></script>
<script src="ads.js" async></script>
```

Первым выполнится тот скрипт, который быстрее скачается. Скрипт может выполниться до того, как браузер разберёт весь HTML, поэтому часть элементов страницы ему может быть ещё недоступна.

`async` не задерживает событие [`DOMContentLoaded`](/js/event-domcontentloaded/). Скрипт может выполниться и до него, и после. Если подписаться на `DOMContentLoaded` внутри такого скрипта, обработчик может не сработать никогда: событие уже прошло.

Проверьте `document.readyState` перед подпиской:

```js
if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', init);
} else {
  init();
}
```

### Атрибут `defer`

Браузер выполняет скрипт после разбора HTML, но до события `DOMContentLoaded`. Событие ждёт, пока выполнятся все скрипты с `defer`.

```html
<script src="library.js" defer></script>
<script src="app.js" defer></script>
```

Первым всегда выполнится `library.js`, который подключён раньше. Даже если `app.js` скачается быстрее, браузер выполнит его вторым, и к этому моменту библиотека уже будет готова.

## Применение

`defer` подходит для скриптов, которым нужен доступ ко всему [DOM-дереву](/js/dom/) или важен порядок выполнения. Такие скрипты можно подключать прямо в [`<head>`](/html/head/): браузер начнёт скачивать их раньше, а выполнит, когда HTML будет разобран.

А `async` хорош для независимых скриптов, например аналитики и рекламы, порядок выполнения которых не важен.

## Подсказки

💡 Если указать оба атрибута, сработает `async`. Раньше `defer` писали рядом с ним как запасной вариант для браузеров без поддержки `async`.

💡 В скриптах с `async` и `defer` браузер игнорирует `document.write()`. Перед тем как добавить атрибут, проверьте, что скрипт не использует этот вызов.

💡 Браузер заранее просматривает разметку в поисках ресурсов. Поэтому обычный скрипт он может начать скачивать раньше, чем дойдёт до него. Но выполнит скрипт всё равно на его месте, и до этого разбор HTML не продолжится.

💡 Скрипты-модули с `type="module"` браузер и так выполняет как с `defer`, поэтому этот атрибут им не нужен. А `async` работает у модулей, даже у встроенных, без `src`.

💡 Внешний скрипт, созданный через `document.createElement()`, браузер выполняет как с `async`. Чтобы несколько таких скриптов выполнялись по порядку, задайте им `script.async = false` до вставки на страницу. Разбор HTML они ждать не будут, так что это не замена `defer`.

💡 `<script>`, вставленный через [`innerHTML`](/js/element-innerhtml/), браузер не выполнит вовсе.
