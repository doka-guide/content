## Кратко

_ARIA-атрибуты_ — это группа дополнительных атрибутов из [спецификации WAI-ARIA](/a11y/aria-intro/#specifikaciya), которая состоит из свойств и состояний.

_Состояния (states)_ описывают состояния элементов и отвечают на вопрос «В каком состоянии сейчас элемент?».

_Свойства (properties)_ нужны для раскрытия дополнительных функций элементов. Отвечают на вопрос «Что ещё делает этот элемент?».

ARIA-атрибуты дополняют [роли](/a11y/aria-roles/). Браузер передаёт их через [Accessibility API](/a11y/screenreaders/#accessibility-api) вспомогательным технологиям, например, скринридерам. Сами по себе, без CSS и JavaScript, ARIA-атрибуты не изменяют внешний вид и функциональность элементов.

## Как пишется

Общий синтаксис ARIA-атрибутов — `aria-атрибут="значение"`.

Для примера сообщим [скринридеру](/a11y/screenreaders/) с помощью ARIA-атрибута, что у поля есть инструкция к нему.

```html
<label for="psw">Пароль</label>
<input
  type="password"
  name="password"
  id="psw"
  aria-describedby="hint"
>
<span id="hint">
  Пароль должен содержать не меньше 20 знаков
</span>
```

[`aria-describedby`](/a11y/aria-describedby/) связывает с помощью одинакового ID два элемента — поле и подсказку из тега [`<span>`](/html/span/). Скринридер озвучит текст подсказки после подписи и основной информации о поле.

В разные атрибуты можно добавлять разные типы значений, не только ID.

Для каких-то атрибутов в качестве значения используют произвольный текст, как для [`aria-label`](/a11y/aria-label/):

```html
<button aria-label="Копировать">
  <img src="copy-icon.svg" alt="">
</button>
```

Есть атрибуты, которые принимают булевы значения `true` или `false`. Например, [`aria-hidden`](/a11y/aria-hidden/):

```html
<span aria-hidden="true">×</span>
```

Для других атрибутов используют конкретные токены. К примеру, для [`aria-live`](/a11y/aria-live/):

```html
<div class="alert" aria-live="assertive"></div>

<div class="error" aria-live="polite"></div>
```

Если оставить значение пустым, браузер посчитает, что атрибута нет, и возьмёт значение по умолчанию. У `aria-invalid` это `false`, а у `aria-pressed` — `undefined`. Кнопка с `aria-pressed=""` для скринридера вообще не переключатель.

Поэтому лучше задавать атрибутам конкретные значения:

```html
<label for="psw">Пароль</label>
<input
  type="password"
  name="password"
  id="psw"
  aria-describedby="error"
  aria-invalid="false"
>
<!-- В поле нет ошибки, -->
<!-- поэтому скрипт не добавил текст в <span> -->
<span id="error"></span>
```

[Список всех типов значений атрибутов](https://www.w3.org/TR/wai-aria-1.2/#propcharacteristic_value) есть в спецификации WAI-ARIA 1.2 (Web Accessibility Initiative — Accessible Rich Internet Applications 1.2).

## Правила использования

- Для HTML-тегов сначала используйте HTML-атрибуты, а уже потом думайте об ARIA-атрибутах.
- Глобальные атрибуты можно задавать почти любым элементам. Для остальных уточняйте, сочетаются ли они с явной или встроенной ролью элемента.
- Кастомным интерактивным элементам нужны ARIA-атрибуты, которые описывают их состояние. У нативных `<button>`, `<a>` и `<input>` большинство состояний уже есть. Им добавляют только те, которых нет в HTML. Например, `aria-expanded` кнопке, которая раскрывает блок.
- Следите за тем, какие значения можно использовать для атрибутов.
- Старайтесь не оставлять значение атрибута пустым.
- Значения большинства атрибутов можно динамически изменять.

## Типы атрибутов

Атрибуты делятся на группы по функциям и по тому, с какими ролями они сочетаются.

[Список всех ARIA-атрибутов](https://www.w3.org/TR/wai-aria-1.2/#state_prop_def) с их подробным описанием есть в спецификации WAI-ARIA 1.2.

### Глобальные атрибуты

Глобальные атрибуты — самый универсальный тип. Их можно задавать элементам с любыми ролями.

- [`aria-atomic`](/a11y/aria-atomic/) (свойство) — о каком объёме изменений сообщит вспомогательная технология на основе значения `aria-relevant`. Это вся «живая» область или её часть.
- [`aria-busy`](/a11y/aria-busy/) (состояние) — вспомогательная технология может подождать, пока элемент окончательно изменится.
- [`aria-controls`](/a11y/aria-controls/) (свойство) — элемент управляет другим элементом или их группой.
- [`aria-current`](/a11y/aria-current/) (состояние) — текущий элемент из контейнера или группы элементов.
- `aria-describedby` (свойство) — ID одного или нескольких элементов с кратким описанием этого элемента.
- [`aria-details`](/a11y/aria-details/) (свойство) — ID элемента с подробным описанием этого элемента.
- `aria-dropeffect` (свойство) — что произойдёт, когда объект «бросят». Устарело.
- [`aria-flowto`](/a11y/aria-flowto/) (свойство) — следующий элемент в альтернативном порядке чтения. Скринридер может перейти к нему по выбору пользователя, а не по порядку в коде. Поддержка у атрибута слабая.
- `aria-grabbed` (состояние) — объект «схвачен». Устарело.
- `aria-hidden` (состояние) — элемент скрыт из [дерева доступности](/a11y/a11y-tree/) и недоступен для вспомогательных технологий.
- [`aria-keyshortcuts`](/a11y/aria-keyshortcuts/) (свойство) — сочетание клавиш, которое разработчик добавил для взаимодействия с элементом.
- `aria-label` (свойство) — имя элемента.
- [`aria-labelledby`](/a11y/aria-labelledby/) (свойство) — один элемент или несколько содержат подпись для другого.
- `aria-live` (свойство) — элемент изменится, и насколько важно об этом сообщить.
- [`aria-owns`](/a11y/aria-owns/) (свойство) — один элемент или несколько связаны с другими как родители или дети визуально, функционально или в контексте, но это не отражено в [DOM](/js/dom/).
- [`aria-relevant`](/a11y/aria-relevant/) (свойство) — вспомогательная технология объявит об изменениях в «живой» области после определённых изменений в дереве доступности.
- [`aria-roledescription`](/a11y/aria-roledescription/) (свойство) — описание роли на естественном языке.

Но не все глобальные атрибуты подходят любой роли. Некоторым ролям имя задавать запрещено. Поэтому `aria-label` и `aria-labelledby` нельзя ставить, например, на `<div>` и `<span>` с их ролью `generic`.

В ARIA 1.1 глобальными были ещё `aria-disabled`, `aria-errormessage`, `aria-haspopup` и `aria-invalid`. В ARIA 1.2 их глобальное использование устарело. Задавайте их только элементам с подходящими ролями.

Также есть глобальные атрибуты из WAI-ARIA 1.3. Эта версия спецификации — пока [рабочий черновик](https://www.w3.org/TR/wai-aria-1.3/) (Working Draft), а не готовый стандарт. Новые атрибуты уже поддерживают Chrome, Edge, Firefox и Safari, но не все скринридеры их озвучивают или выводят на дисплей Брайля.

- [`aria-braillelabel`](/a11y/aria-braillelabel/) (свойство) — имя элемента для [дисплея Брайля](https://ru.wikipedia.org/wiki/%D0%91%D1%80%D0%B0%D0%B9%D0%BB%D0%B5%D0%B2%D1%81%D0%BA%D0%B8%D0%B9_%D0%B4%D0%B8%D1%81%D0%BF%D0%BB%D0%B5%D0%B9).
- [`aria-brailleroledescription`](/a11y/aria-brailleroledescription/) (свойство) — описание роли элемента на естественном языке для дисплея Брайля.
- [`aria-description`](/a11y/aria-description/) (свойство) — описание элемента текстом прямо в атрибуте. Работает как `aria-describedby`, но текста нет на странице, поэтому его получают только вспомогательные технологии.

В свежей редакторской версии черновика (Editor's Draft) появилась отдельная группа — атрибуты имени (Naming Attributes). В неё вошли `aria-label`, `aria-description`, `aria-roledescription`, брайлевские атрибуты и `aria-keyshortcuts`.

### Атрибуты виджетов

Атрибуты для интерактивных элементов, с которыми можно взаимодействовать. Например, для вкладок, выпадающих списков или всплывающих окон.

- [`aria-autocomplete`](/a11y/aria-autocomplete/) (свойство) — как поле предлагает варианты автозаполнения: прямо в поле, списком, обоими способами или никак.
- [`aria-checked`](/a11y/aria-checked/) (состояние) — отмечен или нет интерактивный элемент, например, чекбокс или радиокнопка. Эквивалент в HTML — `checked`.
- [`aria-disabled`](/a11y/aria-disabled/) (состояние) — элемент отключён. В отличие от HTML-атрибута [`disabled`](/html/disabled/), он не блокирует фокус и клики. Отключить сам элемент должен скрипт.
- [`aria-errormessage`](/a11y/aria-errormessage/) (свойство) — ID элемента с сообщением об ошибке для этого поля. Браузер не передаёт эту связь скринридеру, если у поля `aria-invalid="false"` или этого атрибута нет.
- [`aria-expanded`](/a11y/aria-expanded/) (состояние) — элемент раскрыт или свёрнут.
- [`aria-haspopup`](/a11y/aria-haspopup/) (свойство) — элемент раскрывает попап.
- `aria-hidden` (состояние) — элемент скрыт из дерева доступности и недоступен для вспомогательных технологий.
- [`aria-invalid`](/a11y/aria-invalid/) (состояние) — введённые данные не соответствуют нужному формату.
- `aria-label` (свойство) — имя элемента.
- [`aria-level`](/a11y/aria-level/) (свойство) — уровень элемента в иерархии элементов.
- [`aria-modal`](/a11y/aria-modal/) (свойство) — модальность элемента, когда он не скрыт.
- `aria-multiline` (свойство) — можно ли ввести в текстовое поле несколько строк.
- [`aria-multiselectable`](/a11y/aria-multiselectable/) (свойство) — можно выбрать несколько элементов. Эквивалент в HTML — [`multiple`](/html/multiple/).
- [`aria-orientation`](/a11y/aria-orientation/) (свойство) — ориентация элемента на странице.
- [`aria-placeholder`](/a11y/aria-placeholder/) (свойство) — подсказка по заполнению поля. Эквивалент в HTML — [`placeholder`](/html/placeholder/).
- [`aria-pressed`](/a11y/aria-pressed/) (состояние) — нажат или нет переключатель.
- [`aria-readonly`](/a11y/aria-readonly/) (свойство) — значение элемента нельзя изменить, но с элементом можно взаимодействовать и читать его содержимое. Эквивалент в HTML — [`readonly`](/html/textarea/#readonly).
- [`aria-required`](/a11y/aria-required/) (свойство) — обязательное поле или нет. Эквивалент в HTML — [`required`](/html/required/).
- [`aria-selected`](/a11y/aria-selected/) (состояние) — выбран или нет интерактивный элемент.
- [`aria-sort`](/a11y/aria-sort/) (свойство) — как отсортированы данные в колонке (столбце), строке таблицы или сетки.
- [`aria-valuemax`](/a11y/aria-valuemax/) (свойство) — максимальное значение ползунка, индикатора загрузки и других элементов с диапазоном чисел. Эквивалент в HTML — `max` у [`<input>`](/html/input/).
- [`aria-valuemin`](/a11y/aria-valuemin/) (свойство) — минимальное значение ползунка, индикатора загрузки и других элементов с диапазоном чисел. Эквивалент в HTML — `min` у `<input>`.
- [`aria-valuenow`](/a11y/aria-valuenow/) (свойство) — текущее значение ползунка, индикатора загрузки и других элементов с диапазоном чисел. Эквивалент в HTML — [`value`](/html/input/#value) у `<input>`.
- [`aria-valuetext`](/a11y/aria-valuetext/) (свойство) — текстовое описание значений ползунка, индикатора загрузки и других элементов с диапазоном чисел.

### Атрибуты изменяющихся областей

Атрибуты [изменяющихся или «живых» областей](/a11y/live-region/) (live regions) нужны для частей страниц, которые динамически изменяются. К примеру, для сообщений об ошибках, таймеров и оповещений. Их можно применять к любым элементам.

- `aria-atomic` (свойство) — о каком объёме изменений сообщит вспомогательная технология на основе значения `aria-relevant`. Это вся «живая» область или её часть.
- `aria-busy` (состояние) — вспомогательная технология может подождать, пока элемент окончательно изменится.
- `aria-live` (свойство) — элемент изменится, и насколько важно об этом сообщить.
- `aria-relevant` (свойство) — вспомогательная технология объявит об изменениях в «живой» области после определённых изменений в дереве доступности.

### Атрибуты связи

Описывают, как элементы связаны между собой.

- [`aria-activedescendant`](/a11y/aria-activedescendant/) (свойство) — активный элемент из [составного интерактивного элемента](/a11y/aria-roles/#roli-vidzhetov). Например, из меню, сетки или комбинированного списка.
- [`aria-colcount`](/a11y/aria-colcount/) (свойство) — общее количество колонок (столбцов) таблицы, обычной или древовидной сетки.
- [`aria-colindex`](/a11y/aria-colindex/) (свойство) — индекс или позиция колонки (столбца) таблицы, обычной или древовидной сетки в виде числа.
- [`aria-colspan`](/a11y/aria-colspan/) (свойство) — количество колонок (столбцов), которые объединены в ячейку таблицы, обычной или древовидной сетки. Эквивалент в HTML — [`colspan`](/html/tables/#atributy).
- `aria-controls` (свойство) — элемент управляет другим элементом или их группой.
- `aria-describedby` (свойство) — ID одного или нескольких элементов с кратким описанием этого элемента.
- `aria-details` (свойство) — ID элемента с подробным описанием этого элемента.
- `aria-errormessage` (свойство) — ID элемента с сообщением об ошибке для этого поля. Браузер не передаёт эту связь скринридеру, если у поля `aria-invalid="false"` или этого атрибута нет.
- `aria-flowto` (свойство) — следующий элемент в альтернативном порядке чтения. Скринридер может перейти к нему по выбору пользователя, а не по порядку в коде. Поддержка у атрибута слабая.
- `aria-labelledby` (свойство) — один элемент или несколько содержат подпись для другого.
- `aria-owns` (свойство) — один элемент или несколько связаны с другими как родители или дети визуально, функционально или в контексте, но это не отражено в DOM.
- `aria-posinset` (свойство) — текущий порядковый номер или положение элемента из обычного или древовидного списка, когда не все элементы есть на странице сейчас.
- [`aria-rowcount`](/a11y/aria-rowcount/) (свойство) — общее количество строк таблицы, обычной или древовидной сетки.
- [`aria-rowindex`](/a11y/aria-rowindex/) (свойство) — индекс или позиция строки таблицы, обычной или древовидной сетки в виде числа.
- [`aria-rowspan`](/a11y/aria-rowspan/) (свойство) — количество строк, которые объединены в ячейку таблицы, обычной или древовидной сетки. Эквивалент в HTML — `rowspan`.
- `aria-setsize` (свойство) — общее количество элементов из группы, когда не все они отображаются на странице сейчас.

В черновике ARIA 1.3 есть новые атрибуты связи:

- [`aria-colindextext`](/a11y/aria-colindextext/) (свойство) — индекс или позиция колонки (столбца) таблицы и обычной или древовидной сетки в виде текста.
- [`aria-rowindextext`](/a11y/aria-rowindextext/) (свойство) — индекс или позиция строки таблицы и обычной или древовидной сетки в виде текста.

## Подсказки

💡 У семантических тегов и элементов с явными ролями есть свойства и состояния по умолчанию. Чаще всего это `false`, `undefined` или `none`, но не всегда. Например, у роли `alert` значение `aria-live` по умолчанию — `assertive`.

💡 Обязательные атрибуты роли задавайте сами. Если их нет, браузер возьмёт запасное значение, но оно редко подходит. Например, заголовок с ролью `heading` без `aria-level` будет второго уровня.

💡 Если меняете роль семантического тега, меняются и значения атрибутов по умолчанию для этой роли. Состояния из HTML сохраняются, если новая роль их поддерживает.

```html
<!-- Скринридер объявит включённый переключатель -->
<input type="checkbox" role="switch" checked>
```

💡 Большинство ARIA-атрибутов не наследуются: `aria-label` или `aria-checked` на родителе ничего не меняют у детей. Но некоторые действуют на всё содержимое: атрибуты «живых» областей, `aria-disabled` и `aria-hidden`.

💡 `aria-hidden` убирает из дерева доступности весь элемент вместе с содержимым. Кнопка или ссылка внутри пропадёт для скринридера, но останется доступной с клавиатуры.

```html
<!-- Так делать не нужно -->
<div aria-hidden="true">
  <button>Закрыть</button>
</div>
```

Поэтому `aria-hidden="true"` нельзя ставить на элементы, внутри которых есть фокусируемые. Чтобы скрыть фон под модальным окном, используйте [`inert`](/html/inert/) или [`<dialog>`](/html/dialog/), который открыт через `showModal()`.

💡 Значения HTML-атрибутов перезаписывают значения ARIA-атрибутов. Исключения — атрибуты имени и описания: `aria-label`, `aria-labelledby`, `aria-describedby` и `aria-description`.

```html
<!-- Так делать не нужно, пример только показывает приоритет -->
<!-- Браузер проигнорирует aria-checked и сообщит -->
<!-- настоящее состояние чекбокса: он отмечен -->
<label>
  <input
    type="checkbox"
    checked
    aria-checked="false"
  >
  Подписаться на рассылку
</label>

<!-- Скринридер прочтёт «Закрыть окно» из aria-label, -->
<!-- а не «Крестик» из alt -->
<img src="cross.svg" alt="Крестик" aria-label="Закрыть окно">
```
