_Изменяющаяся, или «живая», область (live region)_ — это часть страницы, где происходят изменения, о которых автоматически расскажут пользователям [скринридеры](/a11y/screenreaders/) и другие вспомогательные технологии.

Без изменяющейся области скринридер молчит, когда форма показала ошибку или изменения сохранились. Пользователь узнаёт о них случайно, если сам дойдёт до нужного места.

## Когда и как использовать

Изменяющиеся области охватывают любое содержимое на странице, которое добавляется, удаляется или загружается. Например:

- ошибки к полям и целым формам;
- сообщения об успешных действиях пользователя;
- оповещения;
- прогресс загрузки или удаления;
- логи, чаты с сообщениями, списки друзей, ленты новостей;
- таймеры;
- бегущие строки с курсами акций, прогнозы погоды, карусели.

Основные правила использования изменяющихся областей:

- В области находится только изменяющееся содержимое. Не делайте изменяющейся областью всю страницу.
- Не делайте изменяющимися областями все части страницы с изменениями. Например, об ошибке в форме рассказать важно, а об изменении названия кнопки не всегда.
- Не делайте область там, где хватит встроенной роли тега или другого ARIA-атрибута. Например, кнопке, которая раскрывает меню, достаточно состояния [`aria-expanded`](/a11y/aria-expanded/).
- Скринридер объявляет только текст области, без ролей элементов внутри. Поэтому кнопки и ссылки держите снаружи области. Роль [`alert`](/a11y/role-alert/) задавайте только тексту.
- Размещайте изменяющуюся область рядом с элементом, который приводит к изменениям. Если пользователь пропустил объявление, он найдёт сообщение рядом с кнопкой. Не связывайте кнопку с областью через [`aria-describedby`](/a11y/aria-describedby/): скринридер будет читать текст области как описание кнопки, даже когда сообщение устарело.

Область срабатывает, когда меняется её содержимое в [DOM](/js/dom/) и [дереве доступности](/a11y/a11y-tree/). Обычно для этого нужен JavaScript 🪄

Скринридер объявляет только изменения в области, которая уже есть на странице. Он часто промолчит, если:

- вставить в DOM готовую область с текстом;
- добавить роль или атрибут области одновременно с текстом;
- текст был в области при загрузке страницы.

Поэтому заранее добавьте в разметку пустую область. Потом меняйте её содержимое с помощью JavaScript, например через свойство `textContent`. Подробнее о работе с элементами — в статье «[Element](/js/element/)».

Для роли `alert` черновик новой версии ARIA делает исключение: скринридер объявит её текст и при появлении элемента на странице. Поддержка неровная, поэтому и для `alert` держите пустую область заранее.

Внутри области можно показывать и скрывать элементы. Для этого меняют значения [`display`](/css/display/) с `none` на `block`, [`visibility`](/css/visibility/) с `hidden` на `visible` или удаляют и добавляют [HTML-атрибут `hidden`](/html/global-attrs/#hidden).

## Как добавить

Есть несколько способов:

- использовать тег `<output>`, в который уже встроена роль изменяющейся области;
- использовать [ARIA](/a11y/aria-intro/)-атрибуты `aria-live` и опционально `aria-busy`, `aria-atomic` или `aria-relevant`;
- добавить к тегам специальные ARIA-роли `status`, `log`, `alert`, `marquee` и `timer`.

### HTML-теги

Первый полезный тег — [`<output>`](/html/output/). В нём выводят результаты: расчёт в калькуляторе или пропущенное слово в тесте по грамматике. Ещё `<output>` подходит для всплывающих уведомлений (тостов). Они выезжают внизу или вверху экрана и исчезают через какое-то время.

Внутри тега размещайте только фразовый контент: текст и строчные теги вроде [`<span>`](/html/span/) и [`<strong>`](/html/strong/). Заголовки, списки, параграфы и таблицы внутрь `<output>` класть нельзя. Кнопки и ссылки формально разрешены, но, как и в любой области, держите их снаружи.

Скринридеры объявляют содержимое `<output>` благодаря встроенной [роли `status`](/a11y/role-status/). У неё невысокий приоритет: скринридер объявит изменения после более важной информации. Например, после сообщения о нажатой кнопке или текста ошибки с ролью `alert`.

Сбоит только VoiceOver в Safari на macOS: он может пропустить текст или объявить его дважды.

Пример всплывающего уведомления с `<output>` 🧇 Обратите внимание, что кнопку для закрытия уведомления добавляем рядом с изменяющейся областью, а не внутри.

```html
<button>Сохранить</button>

<div>
  <output></output>
  <button aria-label="Закрыть">X</button>
</div>
```

Второй тег — [`<progress>`](/html/progress/). Его используют для индикаторов выполнения задач, или прогресс-баров. Это может быть индикатор загрузки файла или очистки папки с удалёнными письмами.

В тег по умолчанию встроена роль [`progressbar`](/a11y/role-progressbar/). Это не роль изменяющейся области. Некоторые скринридеры, например NVDA, сообщают о прогрессе звуковым сигналом. Остальные объявляют значение, когда пользователь переходит к элементу.

Если у загрузки есть чёткие начало и конец, задайте `<progress>` атрибуты `max` и `value`. Без них скринридеры не отследят прогресс. Значение `value` обновляйте с помощью JavaScript.

Ещё у `<progress>` должна быть подпись, чтобы пользователи понимали, что загружается. Для видимой подписи используйте [`<label>`](/html/label/), а для доступной только вспомогательным технологиям — [`aria-label`](/a11y/aria-label/).

```html
<!-- Подпись с <label> -->
<label for="progress-bar">Очищаем корзину</label>
<progress id="progress-bar" max="100" value="0"></progress>

<label>
  Очищаем корзину <progress max="100" value="0"></progress>
</label>

<!-- Подпись с aria-label -->
<progress
  aria-label="Очищаем корзину"
  max="100"
  value="0"
></progress>
```

Кнопки, ссылки и заголовки внутри `<progress>` вспомогательные технологии прочитают как простой текст, без ролей.

Посмотрим на прогресс-бар на практике. Для подписи используем `<label>`, с помощью JavaScript обновим значение атрибута `value` и визуальный индикатор в виде числа и заливки.

```html
<label for="progress-bar">Очищаем корзину</label>
<div>0%</div>
<progress id="progress-bar" value="0" max="100"></progress>

<button>Очистить</button>
```

### ARIA-атрибуты

Другой способ сделать часть страницы изменяющейся областью — специальные [ARIA-атрибуты](/a11y/aria-attrs/).

Чаще всего достаточно задать элементу [`aria-live`](/a11y/aria-live/) со значением `polite`. Скринридер объявит изменения, когда закончит читать текущий текст, и не прервёт пользователя. Такое значение подходит для сообщений о сохранении данных, подписке на рассылку, отправке письма.

```html
<form>
  <!-- Поля, чекбоксы и всё, что душе угодно -->
  <button type="submit">Отправить</button>
  <!-- После отправки JavaScript добавит текст:
  «Мы получили вашу заявку. На обработку уйдёт
  3 рабочих дня.» -->
  <span aria-live="polite"></span>
</form>
```

Другое значение `aria-live` — `assertive`. Оно прерывает пользователя, поэтому применяйте его с осторожностью: только для срочных ошибок, о которых надо рассказать прямо сейчас. Например, пропало интернет-соединение и пользователь не может отправить заявку.

```html
<form>
  <!-- Поля, чекбоксы и всё, что душе угодно -->
  <button type="submit">Отправить</button>
  <!-- При ошибке JavaScript добавит текст:
  «У нас проблемы с сервером, так что заявка
  не отправилась. Нам нужно 5 часов, чтобы всё
  починить.» -->
  <span aria-live="assertive" aria-atomic="true"></span>
</form>
```

Последнее значение `aria-live` — `off`. По ARIA 1.2 скринридер объявляет изменения в такой области, только когда на ней фокус. На практике скринридеры обычно молчат и тогда: новое содержимое пользователь услышит, когда сам до него дойдёт.

Остальные ARIA-атрибуты изменяющихся областей необязательные и нужны в особых ситуациях.

[`aria-busy="true"`](/a11y/aria-busy/) просит скринридер подождать с изменениями, пока элемент обновляется. Когда обновление закончилось, атрибут удаляют. Поддержка у атрибута неровная: не все скринридеры объявляют изменения, когда атрибут снимают.

Атрибут пригодится для сложных компонентов. Например, для ленты постов, как в соцсетях, [с ролью `feed`](/a11y/role-feed/). На время загрузки постов задайте ленте `aria-busy="true"`. Так скринридер может отложить обновление ленты до конца загрузки и не собьёт пользователя с места, где он читает.

Саму ленту изменяющейся областью не делайте: скринридер прочитает подряд весь текст новых постов. Лучше коротко сообщите о загрузке в отдельной области с ролью `status`.

```html
<div role="feed" aria-busy="true">
  <!-- Тут загружаются посты -->
</div>

<!-- JavaScript добавит текст: «Загружено 10 постов» -->
<div role="status"></div>
```

Если загрузку показывает `<progress>` и неизвестно, сколько она продлится, свяжите обновляемую часть с прогресс-баром через `aria-describedby`.

```html
<div aria-busy="true" aria-describedby="progress-bar">
  <!-- Содержимое, которое сейчас обновляется -->
</div>

<progress
  id="progress-bar"
  aria-label="Загрузка результатов"
></progress>
```

[`aria-atomic`](/a11y/aria-atomic/) говорит скринридеру, что читать при изменении: всю область или только изменившуюся часть. Атрибут пригодится для таймеров.

Если используете `aria-atomic="true"` в таймере, вспомогательные технологии будут правильно объявлять текущее время: сначала часы, даже если они не изменились, потом минуты. Без атрибута скринридеры расскажут только об изменившихся минутах.

```html
<div role="timer" aria-live="polite" aria-atomic="true">
  <span id="timer-hours"></span>
  <span id="timer-mins"></span>
</div>
```

[`aria-relevant`](/a11y/aria-relevant/) сообщает скринридеру, о каких изменениях рассказать. Атрибут полезен для чата или списка друзей. Значения:

- `additions` — добавленные элементы;
- `text` — добавленный текст;
- `removals` — удалённое содержимое;
- `all` — все изменения.

Значения можно сочетать. В списке друзей важны и новые, и удалённые аккаунты, поэтому задаём `aria-relevant="additions removals"`.

```html
<ul
  id="friend-list"
  aria-live="polite"
  aria-relevant="additions removals"
>
  <!-- Ссылки на аккаунты друзей -->
</ul>
```

<aside>

😥 Имейте в виду, что пока у `aria-relevant` [плохая поддержка](https://a11ysupport.io/tech/aria/aria-relevant_attribute). На практике многие скринридеры не сообщают об удалённом содержимом.

</aside>

### ARIA-роли

HTML пока покрывает не все случаи. Для остальных используйте специальные [ARIA-роли](/a11y/aria-roles/). Лучше задавать их нейтральным [`<div>`](/html/div/) и `<span>`, но иногда подойдут и семантические теги, например [`<p>`](/html/p/).

Чаще всего используют роль `status`. Она подходит для любых изменений, о которых скринридерам не надо срочно рассказывать. Например, что письмо отправлено или что покупка оплачена.

В `status` встроены атрибуты `aria-live="polite"` и `aria-atomic="true"`. Скринридер прочитает всю область, но дождётся паузы и не прервёт пользователя.

```html
<form>
  <!-- Элементы формы для оплаты покупки -->
  <button type="submit">Оплатить</button>
  <!-- После оплаты JavaScript добавит текст:
  «Покупка успешно оплачена. Начинаем собирать
  заказ.» -->
  <span role="status"></span>
</form>
```

[`log`](/a11y/role-log/) подходит для логов. Это часть страницы, куда по порядку добавляются записи: история сообщений, список ошибок, журнал действий программы. Старые записи могут исчезать, когда появляются новые.

```html
<h2>История сообщений</h2>
<div role="log">
  <ul>
    <li>
      Одолжишь своего вельш-корги-кардигана до понедельника?
      Очень нужно.
      <time datetime="2077-04-21T12:09">12:09</time>
    </li>
    <li>
      Тебя снова взломали?
      <time datetime="2077-04-21T13:00">13:00</time>
    </li>
  </ul>
</div>
```

В `log` встроен атрибут `aria-live="polite"`: скринридер объявляет только новые записи и не сразу. Не добавляйте логу `aria-atomic="true"`: тогда на каждую новую запись скринридер перечитает всю историю. Если изменения срочные, добавьте `aria-live="assertive"`.

Роль `alert` нужна редко: только для срочных, важных сообщений после действия пользователя или другого события. Чаще всего это ошибка формы после нажатия на кнопку «Отправить». Ещё пример — пропало интернет-соединение или не получилось сделать денежный перевод.

В `alert` встроены атрибуты `aria-live="assertive"` и `aria-atomic="true"`, так что скринридеры моментально рассказывают обо всём, что происходит в области.

```css
.message {
  display: none;
}

.message.show {
  display: inline-block;
}
```

```html
<div role="alert">
  <!-- JavaScript добавляет и удаляет класс .show -->
  <span class="message">
    Изменения не сохранились из-за проблем с сервером.
  </span>
</div>
```

<aside>

🚑 Для _модального окна_ с невероятно срочным оповещением используйте роль [`alertdialog`](/a11y/role-alertdialog/).

</aside>

Ещё две роли изменяющихся областей: `marquee` и `timer`. В них встроен `aria-live="off"`, поэтому скринридеры не объявляют изменения в них сами.

В черновике новой версии ARIA эти роли планируют убрать из изменяющихся областей. Скринридеры меняют поведение медленно, так что пока считайте `marquee` и `timer` изменяющимися областями.

[Роль `marquee`](/a11y/role-marquee/) подходит для блоков с быстро меняющейся информацией: биржевых курсов и рекламных баннеров. Название досталось от устаревшего тега `<marquee>` для бегущих строк. Новые курсы пользователь узнает, когда сам дойдёт до блока.

```html
<h3>Текущие курсы валют</h3>
<div role="marquee">
  <ul>
    <li>999 956 $ за юань</li>
    <li>1 000 000 000 032 $ за докакоин</li>
  </ul>
</div>
```

[Роль `timer`](/a11y/role-timer/) описывает область с обычным или обратным отсчётом времени. Если таймер обновляется редко, например раз в минуту, добавьте `aria-live="polite"` и `aria-atomic="true"`, как в примере с таймером выше. Секундомеру так делать не стоит: скринридер будет говорить без остановки.

Все особенности ролей изменяющихся областей в одной таблице.

| Роль      | Описание                | Встроенные атрибуты                           |
| --------  | ------------------------| --------------------------------------------- |
| `status`  | Несрочные изменения.    | `aria-live="polite"`, `aria-atomic="true"`    |
| `log`     | Изменения в логах.      | `aria-live="polite"`                          |
| `alert`   | Срочные изменения.      | `aria-live="assertive"`, `aria-atomic="true"` |
| `marquee` | Сменяющаяся информация. | `aria-live="off"`                             |
| `timer`   | Отсчёт времени.         | `aria-live="off"`                             |

## Метод `ariaNotify()`

Метод `ariaNotify()` из [спецификации WAI-ARIA](https://w3c.github.io/aria/#ARIANotifyMixin) передаёт текст уведомления вспомогательным технологиям напрямую. Изменяющаяся область для этого не нужна: на странице не появляется элемент с текстом, а скринридер всё равно объявит сообщение.

Метод есть у `document` и у любого элемента. Вызывайте его у элемента, к которому относится сообщение: язык озвучки браузер берёт из атрибута [`lang`](/html/global-attrs/#lang) этого элемента.

Аргументы метода:

- строка с текстом уведомления;
- необязательный объект с опцией `priority`: `high` для срочных уведомлений или `normal` (по умолчанию) для остальных.

```js
document.ariaNotify('Письмо отправлено.')

const form = document.querySelector('form')
form.ariaNotify('Не удалось отправить письмо.', {
  priority: 'high'
})
```

Если на странице есть изменяющиеся области, их объявления перебивают уведомления `ariaNotify()`.

<aside>

⚠️ `ariaNotify()` поддерживают Chrome и Edge с версии 141, Firefox со 150 и Safari с 27. В macOS VoiceOver может пропустить уведомление, если в тот же момент на странице происходит другое событие, например переходит фокус. Тогда VoiceOver объявит это событие вместо уведомления.

</aside>

Для старых браузеров оставьте запасной вариант с изменяющейся областью:

```js
const status = document.querySelector('[role="status"]')
const message = 'Письмо отправлено.'

if ('ariaNotify' in document) {
  document.ariaNotify(message)
} else {
  status.textContent = ''
  setTimeout(() => {
    status.textContent = message
  }, 100)
}
```

Область сначала очищаем, а текст записываем с небольшой задержкой. Если записать тот же текст сразу, скринридер может не заметить изменения и промолчать.

Проверка `'ariaNotify' in document` не поможет в ChromeOS: там метод есть, но скринридер не объявляет уведомления.
