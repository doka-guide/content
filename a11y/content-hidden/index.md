## Кратко

В статье разберём три частых случая:

- скрыть содержимое от [скринридеров](/a11y/screenreaders/), но оставить на экране;
- скрыть содержимое с экрана, но оставить для скринридеров;
- скрыть содержимое от всех.

Когда может понадобиться скрыть содержимое только для пользователей скринридеров? К примеру, когда на странице сайта часто повторяются декоративные элементы, например иконки рядом с текстом. Повторяющееся содержимое не помогает пользователям скринридеров, так что его можно не показывать им.

Бывает и наоборот: зрячий пользователь понимает элемент по виду, а пользователю скринридера нужен текст. Например, кнопке с иконкой лупы рядом со строкой поиска нужно имя. Его можно спрятать с экрана, но оставить для скринридера.

## ARIA-атрибут `aria-hidden`

Можно использовать атрибут [`aria-hidden`](/a11y/aria-hidden/) со значением `true`, чтобы скрыть содержимое от скринридеров, но оставить его видимым на странице.

```html
<p aria-hidden="true">
  Этот текст виден на странице, но скрыт от скринридера.
</p>
```

Атрибут прячет и всё содержимое элемента, в том числе вложенные кнопки и ссылки. Вернуть их через `aria-hidden="false"` нельзя.

Вложенные кнопки и ссылки остаются в порядке фокуса. Что будет дальше, зависит от браузера:

- в Firefox пользователь скринридера попадает на элемент, о котором скринридер ничего не может сказать;
- Chrome и Safari при фокусе не учитывают `aria-hidden`, и скринридер читает элемент.

Чтобы убрать область и из порядка фокуса, и из [дерева доступности](/a11y/a11y-tree/), используйте атрибут [`inert`](/html/inert/). Он выключает область для всех: её кнопки не нажать и мышью. Поэтому атрибут подходит для того, что сейчас не нужно никому, например для страницы под модальным окном.

<aside>

❗️ Не ставьте `aria-hidden="true"` и [`role="presentation"`](/a11y/role-presentation-none/) на видимые элементы, которые получают фокус.

Роль `presentation` удаляет семантику элемента. Но браузер игнорирует эту роль, если элемент может получить фокус или у него есть глобальный ARIA-атрибут, например [`aria-describedby`](/a11y/aria-describedby/). Поэтому `presentation` на кнопке или ссылке бесполезна.

</aside>

## Классы `.visually-hidden`, `.sr-only`, `.off-screen`

Иногда текст нужен скринридеру, но не нужен на экране. Для этого пишут CSS-класс, который прячет содержимое только от глаз. Содержимое с таким классом остаётся частью страницы, поэтому скринридеры его читают.

<aside>

💡 Класс обычно называют `.visually-hidden`, `.vh` или `.sr-only`. `.sr-only` — сокращение от _screen reader only_, «только для скринридеров». Имя класса может быть любым.

</aside>

```css
.sr-only {
  clip-path: inset(50%);
  height: 1px;
  overflow: hidden;
  position: absolute;
  white-space: nowrap;
  width: 1px;
}
```

```html
<p class="sr-only">
  Этот текст скрыт визуально, но доступен
  для скринридеров.
</p>
```

Как работают свойства класса:

- `width` и `height` по 1 пикселю сжимают элемент до точки.
- [`position: absolute`](/css/position/#absolute) убирает элемент из обычного потока документа.
- [`clip-path: inset(50%)`](/css/clip-path/) обрезает и этот пиксель.
- `overflow: hidden` прячет текст, который не помещается в пиксель.
- `white-space: nowrap` не даёт тексту переноситься в узком элементе. Иначе некоторые скринридеры читают слова слитно.

Нулевые размеры не подойдут. Элемент с `width: 0` и `height: 0` остаётся в дереве доступности, но многие скринридеры его не читают.

Применим `.sr-only` к кнопке, у которой вместо текста иконка.

```html
<label for="search">Поиск:</label>
<input id="search" type="text">
<button class="button">
  <span class="sr-only">Искать на странице</span>
  <svg
    aria-hidden="true"
    width="24"
    height="24"
    viewBox="0 0 24 24"
    fill="none"
    stroke="#000000"
    stroke-width="3"
    stroke-linecap="round"
    stroke-linejoin="round"
    xmlns="http://www.w3.org/2000/svg"
  >
    <!-- Описание фигуры -->
  </svg>
</button>
```

<iframe title="Кнопка поиска с иконкой и классом .sr-only" src="demos/hide-text/" height="250"></iframe>

Атрибут `aria-hidden="true"` прячет иконку от скринридера. Тогда браузер собирает [доступное имя](/a11y/accessible-names-and-descs/) кнопки только из текста в `.sr-only`. Текст иконки, например её `<title>`, в имя не попадёт.

Не вешайте `.sr-only` на ссылки и кнопки, которые должны появляться при фокусе, например на ссылку «Перейти к содержимому». Для них сделайте отдельный класс. Он прячет элемент, только пока на нём нет [фокуса](/css/focus/) и [нажатия](/css/active/):

```css
.sr-only-focusable:not(:focus):not(:active) {
  clip-path: inset(50%);
  height: 1px;
  overflow: hidden;
  position: absolute;
  white-space: nowrap;
  width: 1px;
}
```

В старых версиях класса встречается ещё свойство [`clip`](/css/clip/). Его писали для браузеров, которые не понимали `clip-path: inset()`, например для Internet Explorer. Сейчас `clip-path: inset()` поддерживают все браузеры, и `clip` можно не писать.

Другой способ скрыть содержимое — вывести его за пределы вьюпорта.

```css
.off-screen {
  height: 1px;
  left: -100vw;
  overflow: hidden;
  position: absolute;
  white-space: nowrap;
  width: 1px;
}
```

- `position: absolute` убирает элемент из потока страницы;
- `left: -100vw` сдвигает элемент влево на ширину вьюпорта;
- размеры в 1 пиксель и `overflow: hidden` не дают длинному тексту вылезти из блока в видимую область;
- `white-space: nowrap` нужен по той же причине, что и в `.sr-only`.

Не прячьте так ссылки и поля: фокус уйдёт на элемент, которого не видно. На страницах с [`dir="rtl"`](/html/dir/) сдвиг влево может добавить горизонтальную прокрутку.

Для кнопки с иконкой есть способ проще класса. Если элементу нужно только доступное имя, подойдёт атрибут [`aria-label`](/a11y/aria-label/). Он ничего не прячет, а задаёт имя, которое прочитает скринридер:

```html
<button aria-label="Искать на странице">
  <svg aria-hidden="true"><!-- Описание фигуры --></svg>
</button>
```

Где ставить атрибут:

- на ссылки и кнопки можно;
- на `<div>`, `<span>` и `<p>` без роли нельзя: спецификация ARIA запрещает давать им имя;
- полю формы лучше дать видимый [`<label>`](/html/label/).

Если сайт работает на нескольких языках, переводите и текст в `aria-label`.

## Свойства `display: none` и `visibility: hidden`

Эти стили можно применить, если нужно скрыть содержимое от всех пользователей. Браузер убирает содержимое со страницы, и скринридеры его не видят.

```html
<article>
  <p class="visibility-visible">
    Этот текст виден всем пользователям.
  </p>
  <p class="visibility-hidden">
    Этот текст скрыт, но элемент занимает место в потоке.
  </p>
  <p class="display-none">
    Этот текст снова скрыт и не занимает место на странице.
  </p>
</article>
```

```css
.visibility-hidden {
  visibility: hidden;
}

.display-none {
  display: none;
}
```

Цель у свойств одна, но ведут они себя немного по-разному:

- [`visibility: hidden`](/css/visibility/) скрывает элемент, но оставляет его в обычном потоке страницы, и он по-прежнему занимает место.
- [`display: none`](/css/display/) убирает элемент из отрисовки и из дерева доступности. Элемент остаётся в [DOM](/js/dom/), но не занимает места.

У обоих свойств есть исключения:

- если потомку элемента с `visibility: hidden` задать `visibility: visible`, он снова станет видимым и доступным для скринридера;
- текст элемента с `display: none` всё равно может попасть в имя или описание другого элемента через [`aria-labelledby`](/a11y/aria-labelledby/) и `aria-describedby`.

## Атрибут `hidden`

HTML-атрибут [`hidden`](/html/hidden/) работает как `display: none`. Если добавить атрибут к элементу, он скроется со страницы и из дерева доступности и не будет занимать место, как будто его совсем нет.

```html
<p hidden>
  Этот текст не виден на странице и не виден для скринридера.
</p>
```

Браузер скрывает такой элемент через `display: none` в своей таблице стилей. Поэтому ваш CSS может его переопределить: если задать элементу, например, `display: flex`, он снова появится и станет доступен скринридеру.

Из JavaScript атрибут меняют через свойство [`.hidden`](/js/element-hidden/).

У атрибута есть значение `until-found`:

```html
<div hidden="until-found">
  Этот текст найдёт поиск по странице.
</div>
```

Браузер прячет содержимое такого элемента, и скринридер его тоже не видит. Но поиск по странице и переход по якорю находят текст, и браузер сам показывает элемент. Safari пока поддерживает значение частично: он находит текст, но неточно прокручивает к нему.

<aside>

❗️ Не используйте атрибут `hidden`, если хотите скрыть содержимое только визуально. Элемент с `hidden` будет скрыт от всех, включая скринридеры.

</aside>
