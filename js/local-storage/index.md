📚 `localStorage` — один из способов хранить данные в браузере. Обзор всех способов описан в статье «[Хранение данных в браузере](/tools/browsers-storages/)».

</aside>

## Кратко

Это объект в `window`, который долговременно хранит данные в браузере. Данные хранятся парами «ключ — значение». При записи вы указываете ключ, а потом читаете значение по этому ключу.

Значения хранятся в виде строк. Другие типы браузер приводит к строке: если записать число `5`, при чтении вернётся `'5'`.

Не имеет ограничений по времени хранения. Данные может стереть пользователь вручную или браузер автоматически, например когда на устройстве мало места.

В Safari по умолчанию включена защита от отслеживания. С ней Safari удаляет всё, что сайт записал через JavaScript, если пользователь 7 дней пользовался браузером и ни разу не взаимодействовал с этим сайтом.

Максимальный объём данных — около 5 МБ на один источник (_origin_): сочетание протокола, домена и порта.

## Пример

Записываем данные:

```js
window.localStorage.setItem('name', 'Дока Дог')
```

Читаем данные по ключу `name`:

```js
const name = window.localStorage.getItem('name')
console.log(name)
// 'Дока Дог'
```

Если записать по тому же ключу ещё раз, новое значение заменит старое:

```js
window.localStorage.setItem('name', 'Собака Дока')

const name = window.localStorage.getItem('name')
console.log(name)
// 'Собака Дока'
```

## Как понять

Если вам нужно сохранить в браузере небольшие данные на долгое время, например настройки интерфейса, то подойдёт `localStorage`.

`localStorage` работает синхронно: пока он читает или записывает данные, остальной код страницы ждёт. Поэтому для больших объёмов лучше [IndexedDB](https://developer.mozilla.org/ru/docs/Web/API/IndexedDB_API): он работает асинхронно и не блокирует страницу.

⚠️ Любой скрипт на странице, в том числе сторонний или внедрённый злоумышленником через [XSS](/tools/web-security/#cross-site-scripting-xss), может прочитать `localStorage`. Не храните там токены авторизации и персональные данные.

## Как пишется

### Запись

Для записи используйте метод `setItem('ключ', 'значение')`. Он принимает два строковых параметра: ключ, по которому будет сохранено значение, и само значение.

Если данные не помещаются в лимит (около 5 МБ), `setItem()` выбросит исключение `QuotaExceededError` (квота превышена). Старые данные при этом останутся на месте. Поэтому запись оборачивают в [`try...catch`](/js/try-catch/):

```js
try {
  window.localStorage.setItem('name', 'Дока Дог')
} catch (error) {
  if (error.name === 'QuotaExceededError') {
    console.log('Хранилище переполнено')
  }
}
```

### Чтение

Для чтения используйте `getItem('ключ')`. Метод принимает ключ и возвращает значение из хранилища. Если по этому ключу нет значения, метод вернёт [`null`](/js/null-primitive/).

```js
window.localStorage.getItem('name') // вернёт 'Дока Дог'
window.localStorage.getItem('user') // вернёт null
```

### Удаление

Удаляет запись из хранилища `removeItem('ключ')`. Он успешно выполнится, даже если указанного ключа не существует в хранилище.

```js
window.localStorage.removeItem('name')
window.localStorage.removeItem('user')
```

### Очистка хранилища

Метод `clear()` очищает хранилище полностью.

```js
window.localStorage.clear()
```

### Количество полей в хранилище

Свойство `length` показывает, сколько полей в хранилище.

```js
console.log(window.localStorage.length)
// 0
```

### Получение ключа по индексу

Метод `key()` получает ключ по индексу. Порядок ключей спецификация не задаёт, и он может меняться после записи. Поэтому `key()` используют, чтобы перебрать все ключи, а не чтобы найти конкретный.

```js
window.localStorage.setItem('name', 'Дока Дог')
console.log(window.localStorage.key(0))
// 'name'
```

Перебрать все значения можно так:

```js
const localStorageSize = window.localStorage.length
for (let i = 0; i < localStorageSize; i++) {
  console.log(
    window.localStorage.getItem(window.localStorage.key(i))
  )
}
```

### События

Когда страница меняет хранилище через `setItem()`, `removeItem()` или `clear()`, другие открытые страницы того же источника получают [событие](/js/events/) `storage` на `window`. Это соседние вкладки, окна и фреймы. Страница, которая изменила хранилище, это событие не получает.

Если `setItem()` записывает то же значение, что уже было, события не будет.

Событие содержит свойства:

- `key` — ключ, который был изменён (при вызове метода `clear()` ключ будет `null`);
- `oldValue` — старое значение, записанное в поле;
- `newValue` — новое значение, записанное в поле;
- `url` — адрес страницы, на которой вызвано изменение.

```js
window.addEventListener('storage', function (evt) {
  console.log(evt)
})
```
