## Кратко

Элемент — это кусочек HTML в [DOM-дереве](/js/dom/#iz-chego-sostoit-dom). Браузер создаёт DOM для взаимодействия между JavaScript и HTML. Каждый HTML-тег при этом превращается в элемент DOM.

Из DOM можно получить элемент и изменить его. Браузер заметит изменения и отобразит их на странице.

Элементы — один из видов _узлов_ DOM. Узлами бывают ещё текст и комментарии.

## Пример

Поменяем выравнивание и цвет у заголовка `h1`:

```js
// Получаем элемент из DOM
const element = document.getElementsByTagName('h1')[0]

// Выравниваем текст заголовка по центру
element.style.textAlign = 'center'

// Меняем цвет шрифта на красный
element.style.color = 'red'
```

## Как понять

HTML-элементы содержат свойства, которые можно разделить на группы:

- свойства, связанные с HTML-атрибутами: ID, классы, стили и так далее;
- свойства и методы, связанные с обходом DOM: получение дочерних элементов, родителя, соседей;
- информация о содержимом;
- обработка событий;
- специфические свойства элемента.

Первые четыре группы свойств есть у всех HTML-элементов. Специфические свойства отличаются в зависимости от типа элемента. Например, у полей ввода есть свойства, которых нет у параграфов и блоков: `value`, `type` и другие.

### Свойства, связанные с HTML-атрибутами

Читать и записывать значения HTML-атрибутов можно при помощи свойств элемента. Название обычно совпадает с названием атрибута.

`id` — получить идентификатор элемента.

`className` — строка с классами из HTML-атрибута [`class`](/html/class/), разделёнными пробелом.

```js
const element = document.getElementsByTagName('div')[0]

// Напечатать классы в консоль
console.log(element.className)

// Заменить все классы одним
element.className = 'hacked'
```

[`style`](/js/element-style/) — стили элемента. Названия свойств обычно повторяют CSS-свойства, только без дефисов: `margin-top` → `marginTop`:

```js
const element = document.getElementsByTagName('div')[0]

// CSS-свойство background-color
element.style.backgroundColor = 'beige'

// CSS-свойство color
element.style.color = 'gray'

// CSS-свойство margin-top
element.style.marginTop = '20px'
```

### Свойства и методы, связанные с DOM

- `children` — список дочерних элементов;
- `parentElement` — получить родительский элемент;
- `nextElementSibling` и `previousElementSibling` — получить следующий или предыдущий соседний элемент, пропуская текстовые узлы и комментарии;

- [`getElementsByClassName()`](/js/getelementsbyclassname/) — поиск среди всех вложенных элементов по названию класса;
- [`getElementsByTagName()`](/js/getelementsbytagname/) — поиск среди всех вложенных элементов по названию тега;

- [`querySelectorAll()`](/js/query-selector-all/) — поиск всех вложенных элементов, подходящих под CSS-селектор.

### Свойства с информацией о содержимом

[`innerHTML`](/js/element-innerhtml/) возвращает HTML-код всего, что вложено в текущий элемент. При записи браузер заменяет всё содержимое, и страница отобразит новое:

```js
const divElement = document.getElementsByTagName('div')[0]
divElement.innerHTML = '<p>Добавлен из кода</p>'
```

[`outerHTML`](/js/element-outerhtml/) возвращает HTML-код текущего элемента и всего, что в него вложено. При записи в это свойство браузер заменяет в родителе сам элемент новым HTML. Переменная при этом продолжает ссылаться на старый элемент, которого на странице уже нет.

[`textContent`](/js/element-textcontent/) — возвращает текст всех вложенных узлов без HTML-тегов.

### Свойства, связанные с событиями

Чтобы элемент реагировал на события, повесьте на него обработчик. Это можно сделать двумя способами.

#### addEventListener

Современный способ обработки событий — это [`addEventListener()`](/js/element-addeventlistener/).

```js
element.addEventListener('click', (event) => {
  console.log('Клик по элементу')
})
```

Преимущества этого способа:
- на одно событие можно повесить много обработчиков (разные модули могут независимо обрабатывать событие);
- позволяет перехватывать события и [в фазе всплытия, и в фазе погружения](/js/events/#rasprostranenie-sobytiy);
- есть опция `once` для однократного срабатывания, после которого обработчик сам удаляется;
- обработчики можно убрать разом через опцию `signal` и [`AbortController`](/js/abort-controller/);
- с опцией `passive` можно пообещать браузеру не вызывать [`preventDefault()`](/js/event-prevent-default/), и тогда браузер [не ждёт обработчик перед прокруткой](/js/element-addeventlistener/#uluchshenie-proizvoditelnosti-skrolla);
- поддержка пользовательских событий ([`CustomEvent`](/js/custom-event/)).

Недостатки этого способа:
- более многословный синтаксис;
- чтобы убрать обработчик через [`removeEventListener()`](/js/element-removeeventlistener/), нужна та же функция и то же значение `capture`, поэтому анонимную функцию так не убрать;
- из кода нельзя узнать, какие обработчики уже висят на элементе, их видно только в инструментах разработчика.

#### Встроенные обработчики событий

Это свойства DOM-элементов с префиксом `on`: `onclick`, `onchange`, `onsubmit` и другие. В свойство записывают функцию, которая выполнится, когда событие произойдёт.

```js
element.onclick = (event) => {
  console.log('Клик по элементу')
}
```

Строку с кодом можно написать только в одноимённом HTML-атрибуте: `<button onclick="alert('Клик')">`. Если на сайте настроена строгая политика безопасности контента (CSP), браузер такие атрибуты не выполняет.

Преимущества этого способа:
- удобное удаление: достаточно присвоить `null`;
- текущий обработчик можно прочитать из кода: `element.onclick`;
- `return false` в обработчике отменяет действие по умолчанию, а в `addEventListener()` для этого нужен `event.preventDefault()`;
- короткая запись.

Недостатки этого способа:
- на одно событие можно повесить только один обработчик: новое присваивание молча заменяет старый, например, если чужой скрипт перезапишет `onclick`;
- не срабатывает на фазе погружения;
- если нужно однократное срабатывание обработчика, обработчик нужно удалить вручную после срабатывания.

<aside>

💡 Обработчики можно повесить сразу обоими способами. Они выполняются в порядке добавления. Встроенный обработчик встаёт в очередь при первом присваивании, а новая функция занимает то же место:

```js
element.addEventListener('click', () => console.log(1))
element.onclick = () => console.log(2)
element.addEventListener('click', () => console.log(3))
element.onclick = () => console.log(4)
// Клик выведет: 1, 4, 3
```

Если записать `null`, обработчик уходит из очереди, и следующая функция встанет в её конец. HTML-атрибут `onclick` в разметке браузер добавляет ещё при разборе страницы, то есть раньше любого `addEventListener()` на этом элементе.

</aside>

<aside>

💡 Во фреймворках (React, Vue, Angular) используют синтаксис, _похожий_ на встроенные обработчики, но это не настоящие HTML-атрибуты. Внутри фреймворк сам вызывает `addEventListener()`. React, например, вешает свои обработчики на корневой контейнер приложения и оттуда распределяет события по компонентам.

</aside>
