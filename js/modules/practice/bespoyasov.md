🛠 **Избегайте экспортов по умолчанию**. Старайтесь использовать именованные экспорты везде, где это возможно. Это упростит рефакторинг кода и работу в целом.

Некоторые фреймворки могут требовать экспортов по умолчанию. Например, так делает Next.js. В таких случаях другого выхода не остаётся.

🛠 **Используйте реэкспорты**. Чтобы пути импортов не были слишком длинными…

```javascript
import { user } from '../domain/models/user/user.js'
```

…можно использовать реэкспорты: файл импортирует функциональность из модуля и сразу экспортирует её сам. Например, у нас есть такая структура проекта:

```plaintext
domain/
  models/
    user/
      user.js
```

Чтобы сократить путь до модуля _user.js_, можем использовать реэкспорт на уровне _user/_:

```plaintext
domain/
  models/
    user/
      user.js
      index.js
```

```javascript
/* domain/models/user/index.js, первый способ */
import { user } from './user.js'
export { user }

/* domain/models/user/index.js, второй способ */
// Экспорт сразу же
export { user } from './user.js'

/* other-module.js */

// Путь при импорте user.js
import { user } from '../domain/models/user'
```

Сборщики вроде Vite по умолчанию ищут _index.js_ в папке, поэтому в импорте хватит пути до папки. В браузере и в ES-модулях Node.js без сборщика так не получится.

Путь можно сократить ещё сильнее:

```plaintext
domain/
  index.js
  models/
    index.js
    user/
      user.js
      index.js
```

Добавим в каждую папку _index.js_, который реэкспортирует всё из вложенного модуля:

```javascript
/* domain/models/index.js */
export * from './user'

/* domain/index.js */
export * from './models'

/* other-module.js */

// Изменившаяся строчка с импортом из предыдущего примера
import { user } from '../domain'
```

Учтите, что `export *` не реэкспортирует экспорт по умолчанию.

Файлы, которые только реэкспортируют другие модули, называют «бочками» (_barrel files_). Не заводите их на каждом уровне: в больших проектах они замедляют сборщик в режиме разработки и могут мешать ему удалять неиспользуемый код.
