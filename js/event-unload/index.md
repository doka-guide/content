## Кратко

Браузер создаёт событие `unload`, когда выгружает страницу: пользователь закрывает вкладку, переходит на другую страницу или перезагружает её. Отреагировать на него можно, [подписавшись на это событие](/js/events/) у объекта `window`.

⚠️ Не используйте `unload` в новом коде. С версии 155 Chrome на компьютере и Android не создаёт это событие, если сайт не разрешил его заголовком ответа сервера `Permissions-Policy`. Вместо `unload` используйте события `visibilitychange` и `pagehide`.

## Пример

Сохраним черновик из текстового поля, когда пользователь уходит со страницы:

```js
const textarea = document.querySelector('textarea')

window.addEventListener('unload', function () {
  localStorage.setItem('draft', textarea.value)
})
```

В Chrome на компьютере и Android этот код сработает, только если сервер отдаёт страницу с заголовком `Permissions-Policy: unload=(self)`. Надёжнее сохранять черновик на событии `visibilitychange`, когда страница становится скрытой.

## Как пишется

```js
window.addEventListener('unload', function () {
  // ...
})
```

## Как понять

В современном вебе всё увешано трекингом: клики, переходы, прокрутка до определённых секций и ещё куча всего. Почему бы не трекать уход пользователя со страницы?

Раньше для этого подписывались на `unload`. Но у события много проблем:

- на телефонах оно часто не происходит, если браузер закрыли в свёрнутом виде;
- Safari при переходе на другую страницу может положить текущую в кеш для быстрого возврата кнопкой «Назад» и не создать `unload`;
- в Firefox обработчик `unload` не даёт положить страницу в этот кеш, и возврат кнопкой «Назад» работает медленнее;
- Chrome с версии 155 не создаёт его на компьютере и Android, если сайт не разрешил событие в заголовке `Permissions-Policy`.

Chrome отключал `unload` постепенно с 2025 года. Другие браузеры на движке Chromium могут перенять это поведение позже. Chrome на iOS работает на движке WebKit, поэтому там событие пока может происходить.

Вместо `unload` слушают событие [`visibilitychange`](https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event) у `document`. Оно происходит, когда страница становится скрытой: при переключении вкладки, при сворачивании браузера и перед закрытием страницы.

```js
document.addEventListener('visibilitychange', function () {
  if (document.visibilityState === 'hidden') {
    const visitStats = getVisitStats()

    navigator.sendBeacon('/analytics', JSON.stringify(visitStats))
  }
})
```

Метод `sendBeacon()` отправляет данные в фоне. Он не мешает выгрузке текущей страницы и загрузке следующей. Его давно [поддерживают все браузеры](https://caniuse.com/?search=sendbeacon).

`sendBeacon()` ставит запрос в очередь и возвращает `true`, но это не гарантия доставки. У очереди общий лимит на все запросы, обычно 64 КиБ. Если новые данные в него не влезают, метод вернёт `false`.

Если передать в `sendBeacon()` обычный объект, сервер получит строку `[object Object]`. Поэтому данные сначала переводят в JSON. JSON уходит строкой с типом `text/plain`. Читайте тело на сервере как текст и разбирайте JSON сами.

Событие `visibilitychange` может произойти несколько раз за визит, например при каждом переключении вкладки. Учитывайте это при подсчёте данных.

Если нужно поймать именно уход со страницы, подойдёт событие `pagehide` у `window`. Оно происходит и тогда, когда браузер кладёт страницу в кеш для быстрого возврата кнопкой «Назад». Но на телефоне и оно может не произойти, если система закрыла свёрнутый браузер.

> Раньше разработчики использовали ~~костыльные~~ специальные техники, чтобы отправить что-либо в момент закрытия страницы:
>
> - синхронные вызовы `XMLHttpRequest`;
> - картинки со специальными `src` (так называемые пиксели);
> - иногда даже запускали пустые циклы на несколько секунд.
