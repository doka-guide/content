## Кратко

Метод `focus()` переводит фокус на [DOM-элемент](/js/element/). После этого события клавиатуры приходят на этот элемент.

Фокус нельзя поставить на заблокированный или скрытый элемент. В этом случае `focus()` ничего не делает и не выдаёт ошибку.

## Пример

Представим, что мы работаем с веб-страницей с формой:

```html
<form action="/apply" method="POST">
  <label>
    Имя:
    <input type="text" name="name">
  </label>

  <label>
    Почта:
    <input type="email" name="email" id="email">
  </label>

  <button type="submit">Подать заявку</button>
</form>
```

Чтобы программно установить фокус в поле _Почта_, нужно найти элемент и вызвать на нём метод `focus()`:

```js
const emailInput = document.getElementById('email')
emailInput.focus()
```

После выполнения кода в поле появится курсор, и можно сразу печатать.

В демке выберите поле в списке и нажмите кнопку. Фокус перейдёт в выбранное поле:

<iframe title="Перенос фокуса на элемент" src="demos/" height="480"></iframe>

## Как пишется

Обычно `focus()` вызывают без аргументов, но в него можно передать объект с настройками `preventScroll` и `focusVisible`:

```js
element.focus()
element.focus({ preventScroll: true })
element.focus({ focusVisible: true })
```

По умолчанию браузер прокручивает страницу до элемента в фокусе. С `preventScroll: true` прокрутки не будет. Мобильные браузеры на Android эту настройку не поддерживают и прокручивают страницу всё равно.

Настройка `focusVisible` решает, рисовать ли обводку фокуса. Значение `true` включает обводку, а `false` выключает. С `true` элемент попадает под псевдокласс [`:focus-visible`](/css/focus-visible/).

Без настройки браузер решает сам:

- у полей для ввода текста обводка есть всегда;
- у остальных элементов обводка появится, если она была у прошлого элемента в фокусе.

Настройку `focusVisible` поддерживают Chrome и Edge с 145, Firefox с 104 и Safari с 18.4.

## Как понять

### Что такое фокус?

Фокус в вебе показывает, с каким элементом страницы сейчас работает пользователь. Элемент в фокусе браузеры обычно выделяют обводкой. Он принимает события клавиатуры. Например, когда мы печатаем текст в поле ввода, это поле в фокусе.

Фокус критически важен для людей, которые не могут или не хотят пользоваться мышью. С помощью клавиши <kbd>Tab</kbd> такие пользователи перемещают фокус между интерактивными элементами внутри страницы. Так браузер работает по умолчанию.

Когда браузер отображает страницу, фокус не установлен. При нажатии <kbd>Tab</kbd> фокус встаёт в первый интерактивный элемент сверху страницы. Дальше он идёт по порядку в разметке. Положительный [`tabindex`](/html/tabindex/) меняет этот порядок.

Safari на macOS по умолчанию переходит по <kbd>Tab</kbd> только между текстовыми полями и выпадающими списками, а ссылки и кнопки пропускает. Чтобы пройти по ним, нажмите <kbd>Option</kbd> + <kbd>Tab</kbd> или включите эту возможность в настройках Safari.

На фокус можно влиять с помощью HTML-атрибутов [`autofocus`](/html/autofocus/) и `tabindex`, а также из JavaScript с помощью методов `focus()` и [`blur()`](/js/element-blur/).

### Когда нужен `focus()`?

Бывают случаи, когда нужно программно установить фокус на элемент:

- пользователь открыл модальное окно, и фокус нужно перенести в него, иначе фокус останется на странице под окном;
- сервер вернул ошибку в форме, и фокус нужно перенести на поле с ошибкой;
- в составных элементах интерфейса вроде вкладок или панели инструментов фокус переносят между пунктами стрелками.

Во всех этих случаях фокус нужно переместить не по порядку, не так, как браузер делает по умолчанию. Произвольно переместить фокус позволяет метод `focus()`.

Чаще всего фокус переносят в модальных окнах. Если окно сделано без тега [`<dialog>`](/html/dialog/), фокус переносят вручную через `focus()`: и при открытии, и при закрытии. Ещё фокус нужно удерживать внутри окна, например сделать остальную страницу `inert`. Как устроено доступное модальное окно, подробно разбирает руководство W3C [ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

С `<dialog>` проще. Метод `showModal()` сам переносит фокус внутрь окна, а после закрытия возвращает его на элемент, который был в фокусе до открытия. Обычно это кнопка, которая открыла окно. Вызывать `focus()` вручную здесь не нужно:

```js
const openModalButton = document.getElementById('open-modal-button')
const modalWindow = document.getElementById('modal-window')

openModalButton.addEventListener('click', function () {
  modalWindow.showModal()
})
```

Есть исключение. Safari не ставит фокус на кнопку при клике мышью, поэтому после закрытия окна фокус может оказаться на [`<body>`](/html/body/). Чтобы фокус точно вернулся на кнопку, вызовите `focus()` в обработчике события `close`:

```js
modalWindow.addEventListener('close', function () {
  openModalButton.focus()
})
```

### Не на каждый элемент можно установить фокус

Обычно фокус получают интерактивные элементы, с которыми работают с клавиатуры. Без атрибутов вроде `tabindex` каждый браузер сам решает, какие элементы получают фокус. Во всех современных браузерах `focus()` сработает на таких элементах:

- ссылки [`<a>`](/html/a/) с атрибутом `href`;
- кнопки [`<button>`](/html/button/);
- поля ввода [`<input>`](/html/input/), кроме скрытых (`type="hidden"`);
- выпадающие списки [`<select>`](/html/select/);
- поля многострочного ввода [`<textarea>`](/html/textarea/);
- первый дочерний [`<summary>`](/html/details/) в `<details>`;
- элементы с атрибутом `contenteditable`;
- произвольный элемент, если у него есть атрибут `tabindex`.

Полный перечень критериев описан [в спецификации HTML](https://html.spec.whatwg.org/multipage/interaction.html#focusable-area).

Атрибут [`disabled`](/html/disabled/) отключает фокус у кнопок, полей ввода, `<select>` и `<textarea>`. Атрибут `tabindex` это не отменяет. У ссылок, `<summary>` и обычных элементов вроде [`<div>`](/html/div/) атрибута `disabled` нет, и на фокус он не влияет.

На [`<fieldset>`](/html/fieldset/) атрибут `disabled` блокирует все поля внутри, кроме полей в его первом [`<legend>`](/html/legend/).

Ещё фокус не попадает на скрытые элементы ([`display: none`](/css/display/), [`visibility: hidden`](/css/visibility/)) и на элементы с атрибутом [`inert`](/html/inert/) или внутри родителя с ним.
