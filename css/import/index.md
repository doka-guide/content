## Кратко

Директива `@import` подключает один CSS-файл внутри другого. Так стили можно разложить по нескольким файлам, а на странице подключить только один.

## Пример

Предположим, в проекте для удобства стили разделены на несколько файлов:

1. _fonts.css_ — файл с подключением шрифтов и стилями;
1. _buttons.css_ — файл со стилями для кнопок;
1. _main.css_ — основной файл стилей с остальным CSS-кодом.

Чтобы все стили загрузились вместе со страницей, импортируем отдельные файлы в основной файл _main.css_:

```css
@import "fonts.css";
@import "buttons.css";

/*  Остальной CSS-код */
```

## Как пишется

<aside>

☝️ Пишите импорты в самом верху CSS-файла. Импорт ниже обычных правил браузер проигнорирует.

Выше импортов можно поставить только:

- [`@charset`](/css/charset/);
- объявления слоёв [`@layer`](/css/layer/) без фигурных скобок.

Между самими импортами ничего писать нельзя, даже `@layer`.

</aside>

Равнозначные варианты импорта:

```css
@import "file.css";
@import url("file.css");
```

Путь до файла может быть как абсолютным, так и относительным.

Можно указать, на каких типах устройств применять стили из импортируемого файла:

```css
@import "print-styles.css" print;
@import "screen-styles.css" screen;
```

После пути можно указать составное [медиавыражение](/css/media/) или несколько выражений через запятую:

```css
@import "common.css" screen, print;
@import "tablet.css" (481px <= width <= 768px);
@import "landscape.css" screen and (orientation: landscape);
```

Можно проверить, поддерживает ли браузер свойство или селектор, и подключить стили только при поддержке. Для этого после пути пишут функцию `supports()`. Внутри неё — то же условие, что и в директиве [`@supports`](/css/supports/):

```css
@import "tooltips.css" supports(anchor-name: --tooltip);
@import "cards.css" supports(selector(:has(img)));
```

В этом примере стили из _tooltips.css_ применятся только в браузерах с [якорным позиционированием](/css/anchor-positioning-guide/), а из _cards.css_ — только в браузерах, которые понимают [`:has()`](/css/has/).

Импортированные стили можно положить в каскадный слой. Для этого после пути пишут `layer` с именем слоя в скобках:

```css
@layer reset, theme;

@import "reset.css" layer(reset);
@import "theme.css" layer(theme);
```

Так удобно подключать чужие стили, например, библиотеку компонентов. Ваши правила вне слоёв победят стили библиотеки, даже если у её селекторов выше [специфичность](/css/specificity/).

С [`!important`](/css/important/) всё наоборот: важное объявление из слоя победит важное объявление вне слоёв.

Можно написать `layer` без имени. Тогда стили попадут в анонимный слой. У него нет имени, поэтому добавить в него правила из другого места не получится.

Если нужно всё сразу, порядок такой: путь, `layer`, `supports()`, медиавыражения:

```css
@import "cards.css" layer(components) supports(selector(:has(img))) (width >= 768px);
```

## Как понять

Браузер разбирает основной файл и скачивает файлы из импортов. Пока они не загрузятся, браузер не покажет страницу.

Импортированные правила встают в [каскад](/css/cascade/) на место `@import`, то есть раньше остального кода файла. Поэтому при одинаковой специфичности правило ниже импортов победит правило из импортированного файла.

## Подсказки

💡 Не злоупотребляйте импортами. Браузер узнаёт об импорте, только когда скачает и разберёт файл, в котором он написан. Каждый уровень вложенных импортов добавляет ещё один запрос к серверу, и страница появится на экране позже. Файлы, подключённые в HTML через [`<link>`](/html/link/), браузер находит сразу и скачивает одновременно.

💡 Медиавыражение в импорте не экономит трафик. Chrome, Firefox и Safari скачивают файл, даже когда условие ложно. Стили из него они применят, только когда условие станет верным, например, при повороте экрана.

💡 С `supports()` иначе: если условие ложно, браузер файл не скачает. Но `supports()` в импорте Firefox понимает только с 2023 года, а Chrome и Safari — с 2024-го. Браузер постарше посчитает такое условие ошибкой и не применит файл, даже если сам знает `:has()`.
