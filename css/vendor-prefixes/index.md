## Кратко

Вендорные префиксы — это `-webkit-`, `-moz-` и другие приставки перед именами свойств, селекторов, функций и других сущностей CSS. С ними браузеры раньше выпускали экспериментальные фичи, пока их не стандартизировали. Когда браузер начинал понимать имя без префикса, фича считалась готовой.

Сейчас браузеры почти не выпускают новые фичи с префиксами. Префиксы остались в основном у старых и нестандартных фич.

## Кто такие вендоры?

Чтобы понять, что такое вендорные префиксы и зачем они нужны, надо разобраться, кто и как разрабатывает CSS.

Чтобы CSS во всём мире был единым, над ним работает [_Рабочая группа CSS_](https://www.w3.org/wiki/CSSWG) (CSS Working Group). В неё входят инженеры браузеров и другие эксперты. Группа собирает потребности разработчиков сайтов и описывает возможности CSS в документах — _спецификациях_. Спецификация описывает, как должно работать новое свойство.

Дальше фичу внедряют в браузеры. Каждый браузер разрабатывает отдельная компания — _вендор_ (от англ. vendor — поставщик). Отсюда и слово «вендорный».

Обычно браузеры реализуют фичу по черновику спецификации. В черновике описаны не все технические решения, и сам черновик может меняться. Поэтому каждая команда может делать фичу чуть иначе, а потом переделывать её.

Раньше браузеры выпускали такую фичу в тестовом режиме, с вендорным префиксом. Так было, пока спецификация не стабилизировалась и не появились общие для всех браузеров тесты. Иногда браузер выпускал с префиксом и свою фичу, которой в спецификации ещё не было.

## Префиксы

У основных браузеров такие префиксы:

- `-webkit-` — Safari, Chrome, Opera 15+ и другие браузеры на основе движка WebKit или Blink. Firefox тоже понимает многие свойства с этим префиксом, чтобы сайты, написанные под Chrome и Safari, у него не ломались.
- `-moz-` — Firefox и браузеры на движке Gecko.
- `-o-` — Opera 12 и раньше, на движке Presto. Сейчас не нужен.
- `-ms-` — Internet Explorer и старый Microsoft Edge 12–18. Сейчас не нужен.

## Где нужны префиксы?

В CSS много сущностей: селекторы и [псевдоэлементы](/css/pseudoelements/), свойства и их значения, функции, директивы. Префиксы бывают у любой из них.

### Псевдоэлементы

Префиксы до сих пор нужны псевдоэлементам, которые не вошли в стандарт. Например, ползунок в поле [`<input type="range">`](/html/input/) стилизуют так:

```css
input[type="range"] {
  appearance: none;
}

input[type="range"]::-webkit-slider-thumb {
  appearance: none;
  width: 16px;
  height: 16px;
  border-radius: 50%;
  background-color: #BADA55;
}

input[type="range"]::-moz-range-thumb {
  width: 16px;
  height: 16px;
  border: none;
  border-radius: 50%;
  background-color: #BADA55;
}
```

Из-за префиксов в псевдоэлементах код приходится дублировать. Если перечислить оба селектора [через запятую](/css/selector-list/), Chrome и Safari не поймут `::-moz-range-thumb` и отбросят всё правило целиком.

В Chrome и Safari стили ползунка сработают, только если отключить стандартное оформление. Для этого [`appearance: none`](/css/appearance/) нужен и у ползунка, и у самого поля.

Вместе со стандартным оформлением пропадёт и дорожка. Её оформляют через `::-webkit-slider-runnable-track` и `::-moz-range-track`. Проверьте, что у поля остался [видимый фокус](/css/focus-visible/).

### Значения свойств

Бывает и так, что свойство старое, а значение для него новое. Например, значение `stretch` растягивает элемент на всю доступную ширину. Его понимают:

- Chrome и Edge — с версии 138;
- Safari — с версии 27;
- Firefox — пока только значения с префиксами: `-moz-available`, а с версии 146 и `-webkit-fill-available`.

Поэтому пишут так:

```css
.button {
  width: -webkit-fill-available;
  width: -moz-available;
  width: stretch;
}
```

Браузер читает объявления [`width`](/css/width/) сверху вниз. Значение, которое он не понимает, он пропускает, а понятное применяет вместо предыдущего. Значения с префиксами здесь запасные: они работают, пока браузер не понимает `stretch`. Такое значение называют _фолбэк_.

### Селекторы

Случается, что фича меняется, пока её внедряют. Изначально [псевдокласс](/css/pseudoclasses/) для выбора по нескольким селекторам назывался `:-moz-any()` и `:-webkit-any()`, потом `:matches()`, а в итоге пришли к [`:is()`](/css/is/). Раньше один и тот же селектор приходилось писать трижды:

```css
:-webkit-any(header, footer) a:hover {
  color: red;
}

:-moz-any(header, footer) a:hover {
  color: red;
}

:is(header, footer) a:hover {
  color: red;
}
```

Сейчас `:is()` работает во всех браузерах, и старые варианты писать не нужно.

### Директивы

Раньше префиксы были даже у директив. Например, анимации в Safari до версии 9 и в Chrome до версии 43 работали только с `@-webkit-keyframes`. Сейчас [`@keyframes`](/css/keyframes/) и другие директивы префиксов не требуют.

## Префиксы сегодня

К 2016 году крупные браузеры договорились не выпускать новые фичи с префиксами. В апреле 2016 года к этому правилу присоединился и WebKit, движок Safari.

Префиксы принесли больше вреда, чем пользы. Сайты начинали зависеть от префиксных версий, и браузеры не могли от них отказаться. Иногда браузерам даже приходилось понимать чужие префиксы.

Теперь новые фичи сначала прячут за флагом в настройках браузера или включают на время для сайтов, которые записались на испытания. Когда фича готова, её включают для всех без префикса.

Префиксы остались у старых свойств, которые когда-то вышли с ними, и у нестандартных фич, которые браузеры поддерживают ради совместимости. Например, обрезать текст по числу строк до сих пор можно только через `-webkit-line-clamp`.

## Как всё запомнить?

Скорее всего, вы сейчас думаете, как запомнить, каким свойствам нужны префиксы.

Самый простой способ проверить поддержку свойства — найти его на сайте [Can I use](https://caniuse.com). Там написано, какие префиксы для каких браузеров нужны.

Но чаще всего разработчики не пишут префиксы руками, а используют инструменты автоматизации. Самый популярный из них — [Autoprefixer](https://github.com/postcss/autoprefixer), плагин для PostCSS. PostCSS обрабатывает CSS при [сборке проекта](/tools/bundlers/). У Autoprefixer есть [онлайн-версия](https://autoprefixer.github.io/ru/): вставляете CSS, выбираете браузеры и получаете код с проставленными префиксами там, где это нужно.

## Порядок важен

Свойства и значения с вендорными префиксами пишите выше, чем без префиксов:

```css
.button {
  -webkit-user-select: none;
  user-select: none;
}
```

Если браузер понимает обе записи, он применит последнюю, стандартную.

Например, Safari пока понимает только `-webkit-user-select`. Остальные браузеры понимают [`user-select`](/css/user-select/) без префикса. Запрещайте выделение только у элементов управления вроде кнопок: текст на странице пользователи должны выделять и копировать.
