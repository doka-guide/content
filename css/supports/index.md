## Кратко

Директива `@supports` позволяет проверить, поддерживает ли браузер свойство, другую директиву или CSS-селектор. Если условие срабатывает, браузер применит стили внутри фигурных скобок.

Такие проверки называют _feature queries_.

## Пример

Проверяем, поддерживает ли браузер свойство [`display`](/css/display/) со значением `grid`. Если нет, останется фолбэк — запасные стили на случай, когда браузер не поддерживает свойство:

```css
/* Фолбэк */
.container {
  display: flex;
}

@supports (display: grid) {
  .container {
    display: grid;
  }
}
```

[Грид](/css/grid-guide/) работает во всех современных браузерах, поэтому в демке блоки выстроятся в грид. [Флексбокс](/css/flexbox-guide/) останется только для очень старых браузеров:

## Как понять

Проверка свойств с помощью `@supports` нужна довольно редко, потому что:

1. основные браузеры поддерживают большинство часто используемых CSS-свойств, и дополнительно это проверять не нужно;
1. в браузере есть «нативный фолбэк»: если браузер не понимает пару `свойство: значение`, он просто игнорирует её, и эти стили не применяются.

Но браузер отбрасывает только непонятное объявление и не трогает соседние. Поэтому `@supports` нужен, когда от поддержки свойства зависят другие стили.

Например, мы верстаем блок со свойством [`backdrop-filter`](/css/backdrop-filter/), которое старые браузеры могут не поддерживать. Там, где размытие работает, полупрозрачный фон не нужен. Там, где не работает, без фона текст будет плохо читаться:

```css
.text-block {
  background-color: rgb(141 104 75 / 0.6);
}

@supports (backdrop-filter: blur(8px)) {
  .text-block {
    backdrop-filter: blur(8px);
    background-color: unset;
  }
}
```

Что получится:

- Браузер, который поддерживает `backdrop-filter`, применит оба правила. Селекторы одинаковые, поэтому побеждает правило ниже по коду: фон станет прозрачным, а под блоком появится размытие.
- Браузер без поддержки проигнорирует всё, что написано внутри директивы, и оставит полупрозрачный фон из свойства [`background-color`](/css/background-color/).

Поэтому блок `@supports` пишут после фолбэка. Если поставить его выше, фолбэк вернёт полупрозрачный фон поверх размытия.

Проверьте в демке, что покажет ваш браузер:

Safari до версии 18 знает свойство только с префиксом: `-webkit-backdrop-filter`. Условие из примера там ложно, и останется полупрозрачный фон.

## Как пишется

### Проверка свойства

В круглых скобках после `@supports` пишут свойство и значение, которые нужно проверить. Например, поддержку [пользовательских свойств](/css/custom-properties/):

```css
@supports (--accent: red) {
  .block {
    --accent: #2E9AFF;
    color: var(--accent);
  }
}
```

Значение нужно указать, даже если важна поддержка только самого свойства. Иначе браузер посчитает условие ложным и не применит стили внутри директивы. Такой код не сработает:

```css
@supports (display) {
  .block {
    display: grid;
  }
}
```

### Оператор `not`

В условии можно использовать логические операторы, чтобы строить более сложные проверки.

Оператор `not` пишут после `@supports`, перед скобками с условием. В такой записи браузер применит стили внутри фигурных скобок, если он не поддерживает свойство из круглых скобок:

```css
@supports not (transform: perspective(150px)) {
  div {
    color: red;
  }
}
```

### Оператор `and`

Оператор `and` позволяет проверить сразу несколько условий. Его пишут между условиями, вне круглых скобок. Браузер применит стили внутри фигурных скобок, если все условия верны:

```css
@supports (transform: perspective(150px)) and (display: grid) {
  div {
    display: grid;
    transform: perspective(150px);
  }
}
```

Условий может быть больше двух. Дополнительные скобки вокруг них можно опустить:

```css
/* Со скобками вокруг второго и третьего условия */
@supports (transform: perspective(150px))
  and ((display: grid) and (color: black)) {
  div {
    display: grid;
    transform: perspective(150px);
    color: black;
  }
}

/* Без дополнительных скобок, с тем же результатом */
@supports (transform: perspective(150px))
  and (display: grid)
  and (color: black) {
  div {
    display: grid;
    transform: perspective(150px);
    color: black;
  }
}
```

### Оператор `or`

Оператор `or` позволяет проверить сразу несколько условий. Браузер применит стили внутри фигурных скобок, если хотя бы одно из условий верно:

```css
@supports (transform: perspective(150px)) or (display: grid) {
  div {
    color: #00DD00;
  }
}
```

Условий снова может быть больше двух, а дополнительные скобки так же, как и в примере с `and`, можно опустить.

### Проверка селектора

Селектор проверяют функцией `selector()`. Браузер применит стили в фигурных скобках, если поддерживает селектор внутри неё, например [`:is()`](/css/is/):

```css
@supports selector(:is(ul, ol)) {
  :is(ul, ol) > li {
    color: red;
  }
}
```

### Проверка директивы

Функция `at-rule()` проверяет, знает ли браузер директиву. Незнакомую директиву браузер и так пропустит. Поэтому `at-rule()` нужна, когда от директивы зависят другие стили. Например, от [`@starting-style`](/css/starting-style/):

```css
@supports at-rule(@starting-style) {
  /* Стили, которые нужны только вместе с @starting-style */
}
```

`at-rule()` работает в Chrome и Edge с версии 148 и в Firefox с версии 157. В стабильном Safari функции пока нет.

Если браузер не знает саму функцию из условия, он считает условие ложным, а `not` перед ним — истинным. С директивами старше самой функции это даёт неверный ответ.

`@starting-style` работает в Chrome и Edge с версии 117, в Firefox с версии 129, в Safari с версии 17.5. Но условие из примера окажется ложным:

- в Chrome и Edge 117–147;
- в Firefox 129–156;
- в стабильном Safari.

Поэтому для таких директив `at-rule()` пока ненадёжна. Она пригодится для директив, которые появятся позже неё.

### Проверка шрифтов

Функция `font-tech()` проверяет, понимает ли браузер технологию внутри файла шрифта, например цветные символы:

```css
@supports font-tech(color-COLRv1) {
  .logo {
    font-family: "Color Emoji", sans-serif;
  }
}
```

Шрифт `"Color Emoji"` в примере нужно подключить через [`@font-face`](/css/font-face/), и в его файле должны быть цветные символы в формате COLRv1. Safari такие шрифты не поддерживает, поэтому там условие ложно.

Похожая функция `font-format()` проверяет, понимает ли браузер формат файла шрифта.

### Комбинирование операторов

Операторы можно комбинировать и выстраивать цепочки проверок:

```css
@supports (transform: perspective(150px))
  and ((display: grid) or (display: flex)) {
  div {
    color: #00DD00;
  }
}
```

Операторы `and` и `or` нельзя смешивать без скобок. Если убрать скобки из проверки выше, браузер не сможет разобрать условие. Он отбросит директиву целиком, вместе со всеми стилями внутри:

```css
@supports (transform: perspective(150px))
  and (display: grid)
  or (display: flex) {
  div {
    color: #00DD00;
  }
}
```

В такие комбинации операторов можно включать и функцию `selector()`:

```css
@supports selector(:is(ul, ol)) and (display: grid) {
  :is(ul, ol) > li {
    color: #00DD00;
  }
}
```

### Вложение в другие директивы

Директиву `@supports` можно использовать не только на верхнем уровне CSS, но и внутри других директив.

Например, её можно вкладывать в [`@media`](/css/media/) и наоборот:

```css
/* Такой код валиден */
@supports (display: grid) {
  @media (width <= 768px) {
    .block {
      display: grid;
    }
  }
}

/* Такой код тоже валиден */
@media (width <= 768px) {
  .block {
    display: flex;
  }

  @supports (display: grid) {
    .block {
      display: grid;
    }
  }
}
```

## Подсказки

💡 Пишите фолбэк вне директивы, как в первом примере, а не парой `@supports` и `@supports not`. Так фолбэк применится всегда, а условие будет решать только, заменить ли его. Фолбэк останется, даже если браузер отбросит директиву с ошибкой в условии, например со смешанными `and` и `or` без скобок.

💡 После `not`, `and` и `or` ставьте пробел. Запись `not(display: grid)` браузер примет за неизвестную функцию, и условие станет ложным. А директиву с `and(` или `or(` браузер отбросит целиком.

💡 `not` после `and` или `or` оборачивают в скобки: `(display: grid) and (not (grid-template-columns: subgrid))`. Без них браузер отбросит директиву целиком.

💡 Внутри `@font-face` есть похожая проверка: функция `tech()` в `src` выбирает файл, который браузер поймёт.
