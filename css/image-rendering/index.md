## Кратко

При помощи свойства `image-rendering` можно сообщить браузеру, как интерполировать картинку. Интерполяция — это расчёт цветов пикселей по исходной картинке, когда браузер меняет её размер.

Можно использовать с картинками, фоновыми изображениями в CSS, [`<video>`](/html/video/) и [`<canvas>`](/html/canvas/).

## Пример

Увеличиваем картинку в стиле пиксель-арт без размытия:

```css
.pixel-art {
  width: 400px;
  image-rendering: pixelated;
}
```

## Как пишется

В качестве значений можно использовать одно из ключевых слов.

- `auto` — значение по умолчанию. Браузер сам выбирает алгоритм. Обычно это сглаживание — билинейная интерполяция или похожий алгоритм, который хорошо подходит для фотографий. Чем отличаются алгоритмы, разберём в разделе «[Как понять](#kak-ponyat)».
- `crisp-edges` — браузер сохраняет контраст и резкие границы между цветами и не размывает их. Конкретный алгоритм спецификация не задаёт: это может быть интерполяция по ближайшему соседу или алгоритм, который сглаживает диагональные линии без размытия. Подходит для схем и чертежей из линий.
- `pixelated` — при увеличении каждый пиксель исходной картинки превращается в чёткий квадрат. Это лучший выбор для пиксель-арта.
- `smooth` — сглаживание, например билинейная интерполяция, как для фотографий. Пока его понимает только Firefox.
- `high-quality` — то же, что `smooth`, но браузеру предлагают выбрать более качественный и более затратный алгоритм. Ни один браузер это значение пока не поддерживает.

По спецификации при дробном масштабе `pixelated` должен слегка сглаживать края квадратов, чтобы квадраты не получились разного размера. При уменьшении спецификация требует сглаживать картинку целиком.

На практике Chrome, Firefox и Safari рисуют `crisp-edges` и `pixelated` одинаково: интерполяцией по ближайшему соседу при любом масштабе. Поэтому при дробном масштабе квадраты могут получиться разного размера. При уменьшении браузер пропускает часть пикселей исходной картинки, и тонкие линии могут пропасть.

В демке картинка размером 16 на 16 пикселей. Выберите значения для левой и правой половины, двигайте границу между ними и меняйте масштаб ползунком.

Значение `crisp-edges` без префикса понимают все популярные браузеры. Последними его добавили Chrome и Edge в версии 148 в мае 2026 года. Если важна поддержка более старых Chrome, добавьте запасное значение `pixelated`. Старые Chrome понимают его с версии 41 и рисуют той же интерполяцией по ближайшему соседу:

```css
.diagram {
  image-rendering: pixelated;
  image-rendering: crisp-edges;
}
```

Раньше `crisp-edges` писали с [вендорными префиксами](/css/vendor-prefixes/): `-moz-crisp-edges` для Firefox и нестандартное `-webkit-optimize-contrast` для Safari. Chrome тоже понимает `-webkit-optimize-contrast`, но сглаживает картинку, как при `auto`.

## Как понять

Картинка состоит из сетки пикселей. Когда её растягивают в два раза, пикселей становится в четыре раза больше. Цвета для новых пикселей браузер должен откуда-то взять. Этот расчёт и называется интерполяцией.

Самый простой способ — интерполяция по ближайшему соседу. Новый пиксель получает цвет ближайшего пикселя исходной картинки. Цвета не смешиваются, поэтому картинка остаётся резкой, но при увеличении превращается в набор квадратов. Для пиксель-арта это и нужно, а фотография станет «лесенкой».

Другой способ — билинейная интерполяция. Браузер смешивает цвета четырёх соседних пикселей с учётом расстояния до каждого. Переходы получаются плавными, фотография выглядит естественно, но мелкие детали и резкие границы размываются.

Растягивать картинку приходится и на экранах с высокой плотностью пикселей. На экране с двойной плотностью пикселей обычная картинка в исходном размере занимает вдвое больше физических пикселей по каждой стороне. Поэтому `image-rendering` влияет на неё, даже если в CSS размер не меняли.

Чтобы браузеру не пришлось растягивать картинку, подключите для такого экрана картинку вдвое крупнее. Для этого есть атрибут [`srcset`](/html/img/#srcset) и функция [`image-set()`](/css/image-set/).

Добавить детали, которых не было в исходной картинке, не сможет ни один алгоритм. Если картинку сильно растянуть, она потеряет в качестве при любом значении `image-rendering`.
