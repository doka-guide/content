## Кратко

Псевдокласс `:dir()` выбирает элементы по их вычисленному направлению письма: `:dir(ltr)` или `:dir(rtl)`. Направление задаёт атрибут [`dir`](/html/dir/) на самом элементе или на одном из его предков.

## Пример

Рамка цитаты встаёт к началу строки: слева в `ltr` и справа в `rtl`. За это отвечает логическое свойство [`border-inline-start`](/css/border-inline/), а `:dir(rtl)` перекрашивает рамку у текста справа налево.

```html
<blockquote dir="ltr" lang="ru">
  <p>Направление письма определяет, где начинается строка.</p>
  <div class="lang">dir=ltr</div>
</blockquote>

<blockquote dir="rtl" lang="ar">
  <p>السَّلَامُ عَلَيْكُمْ — مثال على نص باللغة العربية.</p>
  <div class="lang">dir=rtl</div>
</blockquote>
```

```css
blockquote {
  border-radius: 8px;
  padding: 12px 14px;
  border-inline-start: 3px solid #2E9AFF;
}

blockquote:dir(rtl) {
  border-inline-start-color: #F498AD;
}
```

## Как пишется

В скобках указывают одно из двух значений:

- `ltr` — направление слева направо;
- `rtl` — направление справа налево.

Другие значения, например `:dir(auto)`, не считаются ошибкой, но не выбирают ни одного элемента.

```css
/* В тексте слева направо стрелка «Далее» смотрит вправо */
.next:dir(ltr)::after {
  content: "→";
}

/* В тексте справа налево — влево */
.next:dir(rtl)::after {
  content: "←";
}
```

## Как понять

`:dir()` опирается на **вычисленное** направление элемента, а не просто на наличие атрибута `dir`. Браузер вычисляет его так:

1. Если у элемента есть `dir="ltr"` или `dir="rtl"`, берёт это значение.
1. Если у элемента `dir="auto"`, смотрит на текст внутри. Если первой встретится латинская или кириллическая буква, направление будет `ltr`, если арабская или еврейская — `rtl`. Букв нет, например только цифры, — `ltr`. Текст потомков с собственным атрибутом `dir` браузер пропускает. Так же по умолчанию работает тег [`<bdi>`](/html/bdi/).
1. Если атрибута нет, наследует направление родителя. У корневого [`<html>`](/html/html/) без атрибута направление `ltr`.

Поэтому `:dir(rtl)` сработает на потомках элемента с `dir="rtl"`, даже если у них нет собственного атрибута.

Атрибут `lang` на направление не влияет: `<p lang="ar">` без `dir` не станет `rtl` из-за языка, а получит направление родителя. CSS-свойство `direction` тоже не влияет. `:dir()` смотрит на разметку, а не на стили.

### Отличие от селектора `[dir]`

Главное отличие `:dir()` от [атрибутного селектора](/css/attribute-selector/) `[dir="rtl"]`:

- `[dir="rtl"]` выбирает **только те элементы, у которых явно задан** атрибут `dir`;
- `:dir(rtl)` выбирает элементы, у которых **вычисленное** направление `rtl`, включая унаследованное и определённое по тексту через `dir="auto"`.

```html
<div dir="rtl">
  <p>Этот абзац унаследовал направление rtl.</p>
  <p dir="ltr">А этот абзац явно переопределил направление на ltr.</p>
</div>
```

```css
p:dir(rtl) {
  background-color: #FF8630;
}

p[dir="rtl"] {
  border: 2px solid white;
}
```

В этом примере первый абзац получит оранжевый фон от `:dir(rtl)`, но не получит белую рамку от `[dir="rtl"]`, потому что у него нет атрибута `dir`.

### Взаимодействие с `:lang()`

`:dir()` и [`:lang()`](/css/lang/) — это разные псевдоклассы для разных задач:

- `:lang()` выбирает элементы по языку (атрибут `lang`);
- `:dir()` выбирает элементы по направлению письма.

Они не конфликтуют, и их можно комбинировать. Например, селектор `:lang(ar):dir(rtl)` выберет только арабские элементы с направлением справа налево. Порядок псевдоклассов в селекторе не важен.

## Подсказки

💡 Отступы и рамки удобнее задавать [логическими свойствами](/css/logical-properties/) вроде `margin-inline-start` и `padding-inline-end`. Они сами разворачиваются по направлению письма, и писать отдельные правила для каждого направления не нужно. `:dir()` пригодится там, где логического аналога нет. Например, чтобы отразить иконку-стрелку через свойство [`transform`](/css/transform/) со значением `scaleX(-1)`.

💡 Раньше вместо `:dir()` советовали атрибутный селектор `[dir]`. Сейчас это не нужно: `:dir()` работает во всех современных браузерах с декабря 2023 года. К тому же `[dir]` и не был полноценной заменой, потому что не видит унаследованное направление.
