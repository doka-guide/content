# Дока API

Материалы Доки полностью доступны для использования, согласно [лицензиям](license.md). Данный контентный API предоставляет удобный формат взаимодействия для использования в сторонних приложениях.

Здесь собрано всё, что Дока отдаёт программам: JSON с содержимым разделов и данными об участниках, markdown-версии материалов, файлы для ИИ-агентов и MCP-сервер.

## Краткая справка по разделу

Обычно в доках хранится описание методов, свойств, тегов — вы можете использовать их в качестве краткой справки. В своих приложениях или плагинах можно получить такую справку по всем материалам разделов в виде списков:

- HTML: [https://doka.guide/html/index.json](https://doka.guide/html/index.json)
- CSS: [https://doka.guide/css/index.json](https://doka.guide/css/index.json)
- JavaScript: [https://doka.guide/js/index.json](https://doka.guide/js/index.json)
- Рецепты: [https://doka.guide/recipes/index.json](https://doka.guide/recipes/index.json)
- Доступность: [https://doka.guide/a11y/index.json](https://doka.guide/a11y/index.json)
- Веб-платформа: [https://doka.guide/tools/index.json](https://doka.guide/tools/index.json)

Формат информации для каждой доки в списке:

```js
{
  "название доки": {
    "path": "путь к доке",
    "related": [список связанных материалов],
    "summary": [строчки из краткого описания]
  },
}
```

## Информация об участниках

**Краткую информацию** об участниках Доки в виде списка можно получить по ссылке [https://doka.guide/people/info.json](https://doka.guide/people/info.json). Информация доступна в следующем формате для каждого:

```js
{
  "id": "идентификатор участника в Доке",
  "name": "Имя Пользователя",
  "photoURL": "ссылка на аватар пользователя, если есть",
  "pageLink": "ссылка на страницу пользователя",
  "stat": { // количество материалов в разделе
    "наименование раздела": int,
  },
  "practices": { // количество советов в разделе
    "наименование раздела": int,
  },
  "answers": { // количество ответов на вопросы в разделе
    "наименование раздела": int,
  },
  "mostContributedCategory": "раздел с наибольшим вкладом",
  "totalArticles": int, // всего материалов
  "totalPractices": int, // всего советов
  "totalAnswers": int, // всего ответов на вопросы
  "contributionStat": { // активность в репозитории
    "issues": int, // количество ишью
    "pr": int, // количество пулреквестов
  },
  "contributionActions": {}, // действия внутри репозитория
  "url": "ссылка на удобный пользователю ресурс (обычно GitHub)"
}
```

**Полную информацию** об участнике можно получить, зная его идентификатор в Доке, по ссылке такого формата:

```
https://doka.guide/people/{ идентификатор участника в Доке }/info.json
```

Формат данных:

```js
{
  "pageLink": "ссылка на страницу пользователя",
  "name": "Имя Пользователя",
  "url": "ссылка на удобный пользователю ресурс (обычно GitHub)",
  "contributionStat": {}, // активность в репозитории
  "badges": [], // подробный список значков
  "practicesIndex": {}, // подробный список советов с информацией о каждом
  "articlesIndex": {}, // подробный список статей и док с информацией о каждой
  "issuesLink": "https://github.com/doka-guide/content/issues?q=is%3Aissue+author%3Atachisis",
  "pullRequestsLink": "https://github.com/doka-guide/content/pulls?q=is%3Apr+author%3Atachisis"
}
```

## Материал в markdown

Любой материал можно получить в markdown: добавьте `index.md` к адресу страницы.

```
https://doka.guide/css/overflow-wrap/index.md
```

В файле — шапка с метаданными, текст материала и советы из раздела «[На практике](practice.md)». Относительные ссылки на картинки и демки достроены до абсолютных, поэтому их можно открыть как есть.

Формат шапки:

```yaml
---
title: "название материала"
description: "краткое описание"
url: "адрес страницы материала"
section: "название раздела"
createdAt: "дата создания"
updatedAt: "дата последнего изменения"
baseline: [группа и фичи из web-features]
authors: [ники авторов]
contributors: [ники соавторов]
editors: [ники редакторов]
related: [пути к связанным материалам]
isPlaceholder: true # поле есть только у заготовок без текста
source: "ссылка на файл материала в репозитории с контентом"
license: "лицензия текста"
---
```

Пустые поля в шапку не попадают.

Поле `baseline` — имя группы и список фич из [web-features](https://github.com/web-platform-dx/web-features). По ним Дока показывает, готова ли возможность к работе в браузерах. Для программы это источник правды о поддержке: берите `baseline`, а не свои представления о том, что умеют браузеры. Как это устроено, читайте в «[Baseline](baseline.md)».

Поле `isPlaceholder: true` означает, что материала ещё нет. Это заготовка: есть заголовок и адрес, текста нет.

## Файлы для ИИ-агентов

Дока отдаёт два текстовых файла по соглашению [`llms.txt`](https://llmstxt.org):

- [https://doka.guide/llms.txt](https://doka.guide/llms.txt) — краткая справка о проекте: что такое Дока, как получить markdown и JSON, какие есть разделы и сколько в них материалов, на каких условиях всё это можно использовать. Один запрос, несколько килобайт.
- [https://doka.guide/llms-full.txt](https://doka.guide/llms-full.txt) — полный список материалов. Для каждого заголовок, краткое описание и ссылка на markdown-версию. Заготовки в список не попадают.

Начинайте с `llms.txt`: он объясняет, что в Доке есть, и ведёт дальше по ссылкам. `llms-full.txt` нужен, когда надо пройти по всем материалам сразу.

## MCP-сервер

[MCP-сервер Доки](https://github.com/doka-guide/mcp) подключает Доку к ИИ-помощнику в редакторе кода. Помощник ищет материал и читает его целиком, поэтому отвечает по Доке, по-русски и со ссылкой на источник, а не по памяти.

Сервер даёт два инструмента:

- `search_doka` — поиск по материалам всех шести разделов. Отдаёт заголовки, пути и краткие описания;
- `read_doka` — материал целиком в markdown. Сервер сначала просит markdown-версию у сайта, а при неудаче берёт исходник из [репозитория с контентом](https://github.com/doka-guide/content). В исходнике шапка авторская: в ней нет вычисленных полей `url`, `section` и `license`.

Нужен Node.js 20 или новее. Установка в Claude Code:

```bash
claude mcp add doka -- npx -y @doka-guide/mcp
```

Для Cursor и VS Code добавьте блок в файл настроек MCP:

```json
{
  "mcpServers": {
    "doka": {
      "command": "npx",
      "args": ["-y", "@doka-guide/mcp"]
    }
  }
}
```

Чего сервер не делает:

- не ищет по полному тексту материалов. Поиск идёт по заголовкам, описаниям и разделу «Кратко», поэтому точные названия свойств и методов находятся хорошо, а разговорные вопросы хуже. Сервер отдаёт до 20 кандидатов, а выбирает помощник;
- не отдаёт демки. Их надо открывать в браузере по адресу вида `https://doka.guide/css/<материал>/demos/<имя>/`;
- не пишет в репозиторий и не умеет предлагать правки.

Код сервера — под лицензией MIT. Остальное — в [описании репозитория](https://github.com/doka-guide/mcp#readme).

## Как ссылаться на Доку

Тексты материалов распространяются по лицензии CC BY-NC-SA 4.0. Это значит, что при использовании нужно сослаться на страницу материала и назвать Доку источником. Авторов берите из поля `authors`, а подробности — из «[Что можно делать с Докой](license.md)».
