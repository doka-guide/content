Попробуйте отрыть любой вебсайт. Между кликом и моментом, когда сайтом можно будет пользоваться, происходит много всего. Сервер получает запрос и думает над ответом. Браузер скачивает HTML фаил, загружает картинки, скрипты, стили, шрифты, выполняет Javascript и делает промежуточные рендеры страницы. На каждом из этих этапов и после окончательной загрузки могут произойти проблемы: нужные фаилы из-за своих размеров загрузятся только через десять секунд, текст прыгает во время первоночального рендера, кнопка не реагирует на нажатие долгое время. Все это производительность и очень долгое время не существовало понятных метрик, как можно сравнить сайты между собой и что нужно улучшать разработчикам.

В 2020 году компания Google предложила набор метрик, которые описывают визуальный опыт человека конкретными цифрами и назвала их **Web Vitals**. Самые важные из них получили статус **Core Web Vitals**, или основные метрики. C 2021 года улучшение этих покозателей уже не только совет - Core Web Vitals официально влияют на ранжирование страницы в поиске. Если две страницы одинакого подходят под запрос, то выше в списке окажется та, что быстрее и стабильнее.

Далее пойдем по порядку - зачем гугл ввел эти метрики, разберем каждую из этих метрик, какие у них пороги, из-за чего их значения могут ухудшится и разберем основные советы под их улучшения.


## Зачем Google ввёл эти метрики

У производительности сайтов существуют две стороны, и обе важны бизнесу:

**Пользовательский опыт.** Вспомните себя. Если вебсайт очень медленно грузится, текст прыгает при наведении, нажатие на кнопку не приводит не к каким действиям, то очень часто вы закроете вкладку и начнете искать альтернативу. Ровно так же будут себя вести посетители вашего сайта - чем медленее сайт и чем он менее стабилен, тем больше людей уйдет, не дойдя до самого важного. Медленный сайт приносит меньше просмотров, меньше заказов, а следственно, и меньше денег. Core Web Vitals и придумали, чтобы поймать три главных раздражителя пользователя - долгая загрузка, медленное реагирование на действие и прыжки элементов на сайте в понятные показатели.

**SEO.** Google встроил Core Web Vitals в сигнал ранжирования Page Experience.

Введение:
• Что такое Core Web Vitals и зачем их ввел Google как одну из метрик ранжирования в поиске;
• Влияние на пользовательский опыт и SEO.

CLS (Cumulative Layout Shift):
• Определение и принцип работы;
• Причины нестабильности макета (динамический контент, шрифты, изображения без размеров);
• Способы улучшения (указание размеров, резервирование места, оптимизация шрифтов).

LCP (Largest Contentful Paint):
• Что измеряет LCP и его значение для производительности;
• Основные факторы, влияющие на LCP (медленный сервер, блокирующие ресурсы, тяжелый контент);
• Способы оптимизации (ускорение загрузки ресурсов, улучшение кэширования, уменьшение размера изображений).

INP (Interaction to Next Paint):
• Разница между INP и устаревшим FID;
• Как измеряется отзывчивость страницы;
• Основные причины задержек (нагрузка на главный поток, тяжелые скрипты, обработка событий);
• Оптимизация отзывчивости (lazy-loading, web workers, минимизация нагрузки на main thread).

FCP (First Contentful Paint):
• Это момент, когда первый текст или изображение становится видимым;
• Показывает, как быстро начинается загрузка страницы.

TTFB (Time to First Byte) – измеряет время отклика сервера:
• Показывает, сколько времени проходит с момента запроса страницы до получения первого байта данных;
• Влияет на все последующие метрики (FCP, LCP и т. д.).

Как измерять и улучшать Core Web Vitals:
• Инструменты: Google PageSpeed Insights, Lighthouse, Web Vitals API и почему некоторые будут давать некорректные данные;
• Подход к анализу и исправлению проблем;
• Практические советы по поддержанию хороших показателей.
