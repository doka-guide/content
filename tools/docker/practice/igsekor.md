Вот где ещё пригодится Docker.

Например, можно запустить свой сервер Minecraft одной командой:

```bash
docker run -e EULA=TRUE -d -p 25565:25565 --name mc \
  itzg/minecraft-server
```

Ключ `-e EULA=TRUE` передаёт переменную окружения: так вы принимаете лицензионное соглашение Minecraft. Образ `itzg/minecraft-server` собрало сообщество, это не официальный образ Docker.

Подобных образов достаточно много на [Docker Hub](https://hub.docker.com). Для ежедневной работы полезнее будут образы с популярными инструментами или сервисами, например:

- [веб-сервер Nginx](https://hub.docker.com/_/nginx);
- [веб-сервер Apache](https://hub.docker.com/_/httpd);
- [линтер SonarQube с поддержкой большого количества языков](https://hub.docker.com/_/sonarqube);
- [инструмент для оценки качества страниц Google Lighthouse](https://hub.docker.com/r/femtopixel/google-lighthouse).

### Попробовать движок сайта без установки

Иногда хочется посмотреть, как работает система управления сайтом (_CMS_, Content Management System). CMS — это веб-приложение, которое позволяет управлять содержимым сайта и внешним видом через веб-интерфейс.

Чтобы такое приложение заработало, нужно установить базу данных, веб-сервер и интерпретатор языка, на котором написана CMS. Но можно и ничего не устанавливать! Docker позволяет запустить CMS одной-двумя командами. После запуска вы сможете работать с CMS через веб-интерфейс в своём браузере или через терминал, если понадобится доступ к файлам и ресурсам приложения.

Запускаем Drupal одной командой:

```bash
docker run --name some-drupal -p 8080:80 -d drupal
```

При установке выберите базу данных SQLite: тогда отдельный контейнер с базой не понадобится.

WordPress без базы данных MySQL или MariaDB не запустится. Как поднять WordPress и базу вместе одной командой, рассказываем в статье «[Мультиконтейнерное приложение и Docker Compose](/tools/docker-compose/)».

### Попробовать новый фреймворк

Docker помогает попробовать новую технологию и не тратить время на установку и настройку. Например, приложение на Node.js легко упаковать в контейнер. Добавьте в проект файл Dockerfile:

```dockerfile
FROM node:lts

# Рабочая папка приложения
WORKDIR /app

# Установка зависимостей по package.json и package-lock.json
COPY package*.json ./
RUN npm ci --omit=dev

# Копирование исходного кода приложения
COPY . .

# Запуск не от root
USER node

# Порт, который слушает приложение
EXPOSE 8080

# Команда запуска приложения
CMD [ "node", "app.js" ]
```

После этого выполните команду:

```bash
docker build .
```

Точка в конце означает, что Docker соберёт образ из текущей папки и по умолчанию возьмёт файл Dockerfile. После ключа `-t` можно задать имя образа:

```bash
docker build -t app .
```

Рядом с Dockerfile положите файл `.dockerignore`. В проекте на Node.js он ещё и не даст `COPY . .` перезаписать зависимости из контейнера вашей папкой `node_modules`:

```text
node_modules
.env
.git
```

После сборки запустите контейнер с приложением внутри него:

```bash
docker run -p 8080:8080 app
```

Приложение внутри контейнера должно слушать адрес `0.0.0.0`, а не `localhost`. Иначе с вашего компьютера оно не откроется.

Можно начать проект на Angular, React или Vue, полностью переместив разработку внутрь контейнера. Популярные редакторы это поддерживают, например в VS Code для этого есть расширение [Dev Containers](https://code.visualstudio.com/docs/devcontainers/containers). Тогда настройки проекта получат все, кто будет с ним работать, а не только вы.

Не бойтесь, что каждый образ, каждая настройка будут занимать много места. Docker повторно использует слои образа, которые уже есть на вашем компьютере.

Но за образами и контейнерами нужно следить, чтобы они не заняли весь диск. Команда `docker system prune` удаляет все остановленные контейнеры, неиспользуемые сети, образы без тега и неиспользуемый кеш сборки. Перед удалением она спрашивает подтверждение. А чтобы запущенные контейнеры не забрали всю оперативную память, задайте им [ограничения](https://docs.docker.com/engine/containers/resource_constraints/).

### Готовить картинки и другие ресурсы

Docker пригодится и для подготовки ресурсов веб-приложения.

С помощью утилиты [ImageMagick](https://imagemagick.org/) можно работать с картинками в консоли. Её можно установить на свой компьютер или использовать готовый образ. Например, так можно изменить размеры картинки:

```bash
docker run --rm -v /your/images:/imgs dpokidov/imagemagick \
  /imgs/sample.png -resize 100x100 /imgs/resized-sample.png
```

Ключ `-v` подключает папку `/your/images` вашего компьютера к контейнеру как `/imgs`. Ключ `--rm` удалит контейнер, когда команда закончит работу.
